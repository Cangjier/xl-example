# C# → xl.md 映射约定

这份文件是**本项目的事实来源**：把 Cangjie 的 C# 代码搬进 `*.xl.md` 时，遇到 xl 表达不了的 C# 形状，统一按下表处理。每条都注明依据（诊断码或规范章节），以及原始签名该写在哪儿。

依据的规范副本在 `C:\Users\Admin\Documents\GitHub\dsh-xl\docs\`：`xl-syntax.md`（语法）、`xl-check.md`（诊断码）、`xl-emit-ts.md`（ts 产物映射）。行号/章节号指该副本。

---

## 1. 三条总原则

1. **规范内能表达的，就照实表达**：类型用中立写法（`Array<T>` / `Map<K,V>` / `string` / `int`），成员照抄名字（含 PascalCase），可见性 / `static` / `readonly` / `async` 都用关键字写出来。
2. **表达不了的，改写 + 正文留原签名**：不静默丢信息。每处改写都在成员正文里写出原 C# 签名，并说明为什么改写。
3. **目标语言细节不进规范骨架**：`override`、`private set`、`IDisposable`、值类型语义这类东西写正文；规范只描述中立契约。

## 2. 映射表

| # | C# 形状 | xl.md 写法 | 依据 |
| --- | --- | --- | --- |
| M1 | 类有多个构造器（重载） | 一个类**至多一个** `## constructor`：保留参数最全的那个，其余重载的原签名写正文 | `E1206`（一个类至多一个构造器） |
| M2 | `params T[] items` | 声明成普通数组参数 `items:Array<T>`；「可变参数」这层语义写正文，由目标语言还原（ts 剩余参数 / C# `params`） | 语法 §8 无 `params` |
| M3 | `out T value` 参数 | 改写成「返回可空值」的查询方法 `=>T \| null`，原签名写正文；调用方先 `ContainsKey` 再取值 | 语法 §8 无 `out` |
| M4 | 实现 BCL 接口（`IDisposable`、`IAsyncDisposable`、`IEquatable<T>` …） | **不写进** `implements`——`implements` 的目标必须在本文档或它的依赖里声明过，否则报错；BCL 接口写在类正文，成员本身仍照常声明 | `E1104`（`implements` 目标未声明） |
| M5 | `struct` / 值类型 | 用 `# class`；「值语义、目标语言用值类型」写正文 | 语法 §2 关键字表只有 `class` |

| M7 | 字段 / 属性无初始化器 | 显式写出**语义等价**的默认值（`= <expr>` 或默认语言代码块），否则 ts 产品过不了 `strictPropertyInitialization` | ts 严格模式 |
| M8 | 类级 `override` / 重写说明 | 写类正文。类下**没有** `## <lang>` 段——类下的二级标题一律按成员解析 | dsh-xl README §7 第 4 条 |
| M9 | `public override string ToString()` | `## method ToString:()=>string`，`override` 写正文 | 语法无 `override` 标注 |
| M10 | `List<T>` / `Dictionary<K,V>` | 中立容器名 `Array<T>` / `Map<K,V>`；原 C# 类型写正文 | `xl-emit-ts` §4 类型表 |
| M11 | 扩展方法（`this` 参数）、`static class` 工具类 | 尚未覆盖，见 §4 待定项 | — |
| M12 | 属性 `{ get; private set; }` | 若是纯数据容器，直接写 `## field`；`private set` 写正文（ts 侧直接暴露字段） | — |

### M1 的取舍说明

`RuntimeObject` 原有两个构造器（`(Type, object?)` 与 `(object?)`），且全项目**没有一处带参调用**——所有调用点用的都是 struct 的隐式无参默认值 `new RuntimeObject()`。因此规范保留参数最全的那个，省略的写正文，并在正文里记下 ts 侧的等价默认写法 `new RuntimeObject(null, null)`。

这是 M1 的通用处理方式：**先看调用点，再决定保留哪个重载**，而不是机械地保留第一个。

### M3 的取舍说明

`RuntimeScope.TryGetValue(string key, out RuntimeObject value)` 改成 `TryGetValue:(key:string)=>RuntimeObject | null`。名字和语义保留，签名按 M3 改写。生成 C# 时再还原成 `out` 形式。

## 3. 已观察到的 xl 实现行为

写规范时踩到过、或验证过的行为，记在这里免得重复试错。

| 行为 | 说明 |
| --- | --- |
| 散文不进 ts 产物 | 成员正文是给**非 ts 通道**的生成上下文（`xl_context`），ts 直出打印器不把它变成注释。所以正文可以写得很细，不会污染产物。 |
| `# dependencies` 的 `xl` 块会生成 ts import | `import { X } from "./x.xl.md"` → 产物里 `import { X } from "./x";`（`.xl.md` 被剥掉）。不需要再手写 ts import 块。 |
| ts 没有 `namespace` 产物 | `# namespace` 只作上下文，落地成目录层级。 |
| `Array<T>` 默认值 | `= []` 直接可用；`Map<K,V>` 用 `new Map()`。 |
| 返回类型可带联合 | `=>RuntimeObject \| null` 正常解析，产物 `: RuntimeObject \| null`。 |
| `xl_build` 按指纹跳过 | 源文件没改时报告 `skipped … (up to date)`，不重写文件。 |
| 产物头 | 每个产物前两行是 `@generated by xl from <源路径>` 与 `xl:sha256:…  xl:target:ts  xl:ver:0.1.0`。 |

`xl check` 上会拦住的、最容易踩的几条：

- `E1104`：`extends` / `implements` 的目标没在本文档或依赖里声明（BCL 接口最常触发，见 M4）。
- `E1206`：一个类声明了多个构造器（见 M1）。
- `W3102`：类 / 接口成员没有散文说明。
- `W3103`：`# namespace` 没有说明。
- `E0005`：源文件带 BOM 或用了 CRLF——本项目要求 UTF-8 无 BOM + LF。

## 4. 语言鸿沟：xl.md 表达不了的 C# 形状

C# 的事实来源是 `cangjie-publish/cangjie`，产物是 ts。下面每条都是**必须**遵守的改写规则；不改写就过不了 `xl check`，或者 ts 跑起来行为不同。

| # | C# 形状 | xl.md / ts 写法 | 依据 |
| --- | --- | --- | --- |
| M13 | `abstract class` / `abstract` 成员 | xl 没有 `abstract` 修饰符。抽象成员写成普通 `## method`，ts 体为 `throw new Error("abstract member: <名字>")`；`virtual` 且默认为空的成员给空 ts 体。`abstract` / `virtual` / `override` 三个标记写正文 | `E1202`（未知修饰符报错） |
| M14 | **方法重载**（不止构造器） | xl 同一类型内成员重名报错。（a）语义相同的重载**合并**成一个 `Array<T>` 参数的方法（`params T[]` 与 `IEnumerable<T>` 天生同类）；（b）语义不同的重载，保留最通用的那个做 `## constructor`，其余改成 `## static method` 工厂（用户指定），命名形如 `From<区分词>` | `E1205`、`E1206` |
| M15 | `ref` 值参数 | 改成**返回值**：`Process(..., ref int index)` → `Process:(..., index:int)=>int`，调用点写成 `i = item.Process(..., i)` | 语法 §8 无 `ref` |
| M16 | `struct`（`Source<T>` / `SourceRange<T>` / `BranchConditionResult` / `RuntimeObject`） | 一律 `# class`。每个值类型提供 `## method Clone:()=>自身`，正文标注「C# 侧是 struct，赋值即复制」。**实测 `Source.Index` 只在构造时赋值**（`Core/Syntax/Source.cs:18`），`Source` 事实上不可变，因此 ts 里共享引用是安全的；只有**整体赋值**一个 `SourceRange` 时才必须 `Clone()` | 语言差异 |
| M17 | `GetType().Name`（XML 标签名） | ts 用 `this.constructor.name`。因此**类名必须与 C# 完全一致**（含大小写）；嵌套类展平后，ts 类名要等于 C# 的 `Type.Name`（**不含**外层类名） | `Token.ToXmlString` |
| M18 | 泛型类型测试 `i is T1` | ts 泛型被擦除，无法 `is T`。改成接受判定器：`(predicate:(item:T)=>bool)`，调用点传 `(x) => x instanceof Foo` | 语言差异 |
| M19 | 运算符重载 / 隐式转换 / 索引器 | xl 无 `operator`。隐式转换 → `## static method From<Type>` 工厂；`==` / `!=` → `Equals` / `NotEquals` 方法；索引器 `this[int]` → `At(index)` / `Set(index, value)` | 语法 §2 |
| M20 | BCL 类型（`Exception` / `Type` / `IDisposable` / `ValueTask` / `List<T>` …） | 不进 `extends` / `implements`（二者目标必须在规范内声明，否则 `E1104`）。类型标注位用 `any` 或中立等价物，原 C# 类型写正文。`Exception` 派生类自带 `Message` 字段 | `E1104` |
| M21 | 参数表里有**函数类型**参数 | 参数表里出现 `=>` 一律改用 M22 的别名写法。根因：dsh-xl `splitTopLevel` 把 `=>` 里的 `>` 当成泛型收尾符，depth 变负，其后的顶层逗号不再切分参数表，报 `E1204`。实测参数表里出现**两个**函数类型必错，`=>` 出现在最后一个参数之前也错 | dsh-xl `src/core/text.js` |
| M22 | 委托类型（`Func<…>` / `Action<…>`） | 函数类型参数**只能出现在参数表最后**：`=>` 会让 depth 变负（M21），它之后只要还有逗号，参数表就切不开。所以函数类型参数是最后一个时可以直接写（如 `SkipNext:(self:Array<T>, index:int, predicate:(item:T)=>bool)=>int`）；后面还要跟参数时改用同文件的 `# type` 别名，如 `# type ValueGetter = (index:number)=>any`。别名不支持泛型参数（实测报 `E1101`），泛型实参退化成 `any`。字段类型与返回类型没有逗号问题 | `E1101` + M21 |
| M31 | C# `char` | xl 的中立类型表里没有 `char`，写 `char` 会被原样搬进 ts 变成未定义标识符（M28）。一律映射成 `string`：C# 的 `Token<char>` 在规范里写 `Token<string>`，`List<char>` 写 `Array<string>` | `E1204` + ts |
| M32 | 嵌套类（`Common.Branch`、`Statement.Reorganization2`） | 实测 token 层**只有 `Branch` 与 `Reorganization` 两种嵌套类**（8 / 28 处），68 个 token 类全是顶层。嵌套类展平成顶层 `# class` 放同一文件，ts 类名用「外层类名 + `Type.Name`」（`AreaAnnotationBranch`、`StatementReorganization2`），以免与核心的 `Branch` / `Reorganization` 撞名。这些类**永远不进 `Data`、不进 XML**，所以 `constructor.name` 与 C# 不一致是安全的；正文标注原 C# 名字 | M17 + ts |
| M33 | 展平后的嵌套类在文件里的**顺序** | 必须写在外层类**之前**。外层类有 `static readonly field AppendIn:<外层>Branch = new <外层>Branch()` 这样的静态字段初始化器，它在类定义时立即求值；若被引用的类声明在文件后面，ts 会命中暂时性死区（TDZ）**运行时**报 `Cannot access '…' before initialization`。xl.md 的声明顺序就是产物顺序，所以把展平的类排前面 | ts TDZ |
| M23 | `Release()` / `Dispose()` 里「把字段逐个置 `null` 交给 GC」 | ts 是托管回收，这部分**不写**，只保留真正有副作用的清理（`Data?.Clear()` → `this.Data.length = 0`）。正文标注差异 | 语言差异 |
| M24 | `[CallerLineNumber]` 等调用方信息参数 | ts 没有等价机制。保留成普通可选参数（缺省 `0`），调用点不传；正文标注「C# 侧由编译器填充」 | 语言差异 |
| M25 | C# 元组（`(int line, int offset)`） | xl 的类型写法里没有元组，一律映射成 `Array<int>`，ts 侧用解构取值。元素名丢失，写进正文 | `E1204` |
| M26 | `# type` 别名的右侧 | 是**原文**、不参与类型映射，所以右侧必须直接写 ts 语法：`# type ValueGetter = (index:number)=>any`（写 `int` 会原样进 ts 产物） | 语法 §6 |
| M27 | 泛型类的**静态**工厂方法 | ts 禁止静态成员引用类的类型参数。工厂一律把类型参数写成 `any`（`SourceRange<any>` / `SyntaxException<any>`），靠 `any` 的双向可赋值性在调用点正常工作 | ts 2302 |
| M28 | xl **不检查类型名是否存在** | `checkType` 接受任意标识符，所以 BCL 类型名（`Exception`）能过 `xl check` 却在 ts 里是未定义标识符。**每个 `xl check` 之后都必须跑 `tsc`**，它才是类型名与 import 的真正闸门 | `E1204` + ts |
| M29 | 泛型基类（`class ReloadMessage<T> : Message<T>`） | xl 的 `extends` 只接受**裸名字**：`resolves()` 是精确字符串匹配，`extends Message<ValueType>` 直接报 `E1104`。做法是给基类的类型参数**默认值**（`# class Message<ValueType = any>`），子类写裸名 `extends Message`，ts 侧实例化成 `Message<any>`。行为不受影响（`any` 双向可赋值），但继承来的成员里类型参数出现的位置退化为 `any`；正文标注原本的 C# 实参 | `E1104` + ts |
| M30 | `abstract` / `virtual` 方法留空的代码块 | 真正「什么都不做」的成员**不要写空的 ts 块**（会报 `W3012`），直接不写代码块——打印器会输出 `{}` | `W3012` |

## 5. 待定项

下一批切片会撞上、但还没定论的问题：

1. **扩展方法**（`Core/Extensions/**`，其中 `TypeExtensions.cs` 有 83 KB）：xl 没有 `this` 参数，也没有 `static class`。倾向做法是模块级 `# method` 落成一个模块文件，并在正文标注「C# 侧是扩展方法」。
2. **嵌套类与 `partial` 类**：`String.StringGuide` 这类嵌套类要展平成顶层类（M17）；`partial class String` 拆在多个文件里，xl.md 是一源一产物——是合并成一份规范还是保留多份，等遇到 `String.cs` 那一族时定。
3. **泛型约束的复杂形态**：xl 只支持 `<T>` / `<T extends X>` / `<K extends string, V = any>`，`where T : struct, new()` 这类约束表达不了。
4. **`layout=type` 布局**：目前用 `layout=file`（一源一产物）。等声明密度上来了再评估是否按类型拆文件。
5. **非 ts 目标**：等 ts 通道稳定后，再考虑用 `-t csharp` 回生成 C#，与原项目逐文件对照。
