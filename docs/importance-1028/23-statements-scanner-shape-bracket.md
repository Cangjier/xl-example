### typescript/tokens/statements/statement-scanner.xl.md（42897B / 1237 行；StatementScanResult、StatementScanner）

- 结构：**工具 / 自造扫描器**。不属于 basic token、也不是 shape/possible/end：`StatementScanResult` 只是一个 `{Status, End}` 结果对象，`StatementScanner` 全是 `static` 方法，输入是 `Array<Token>`（宿主 `Data` 里已流入的代码单元），输出「这条语句到哪一格结束」的三态答案（`NeedMore`/`Complete`/`Mismatch`）。它没有 `ComputeByIndex`/`BuildByIndex`，不实现 `PossibleShape`，也不安装/消费 `CatalogGuide`。

#### 结构

- 三态答案与 40 余个 `Scan*` 分派：`ScanRoot` 按首单元文本分派到 `ScanBody`/`ScanIf`/`ScanFor`/`ScanLoop`/`ScanDo`/`ScanTry`/`ScanCatch`/`ScanFinally`/`ScanReturnOrThrow`/`ScanBreakOrContinue`/`ScanSimpleSemicolon`/`ScanExpressionBody`/`ScanDeclarationBody`/`ScanToSemicolon`，再互相递归。
- 全部判据都是「从某个下标线性走到 `code.length`」，文件内**没有任何** state/share 字段（`PossibleShapeCache` 未被 import）。

#### 偏离

- `[X1]` ● 用一个手写三态扫描器取代 possible/end 的候选收敛：语句边界由 `StatementScanResult(Status, End)` 直接算出，`Status` 的 0/1/2 与 `NeedMore`/`Complete`/`Mismatch` 是 IMPORTANCE 三层机制之外的一套结果协议 — 证据 `statement-scanner.xl.md:21-32`（`# class StatementScanResult` / `## field Status:int` / `## field End:int = -1`）、`:128-144`（`NeedMore()`→`new StatementScanResult(0, -1)`、`Complete(end)`→`(1, end)`、`Mismatch()`→`(2, -1)`）、`:146-289`（`ScanRoot` 先按首单元类型/文本分派，再 `return StatementScanner.Mismatch()`）。
- `[X1]` ● 设计外的进程级开关与**整份文档原文**静态缓存：`AtEOF` 由调用方在扫之前写成 `true` 来改变同一函数的答案，`ContentDocument`/`ContentText` 把整个 `Document` 的 raw 文本抓进静态字段 — 证据 `statement-scanner.xl.md:36-40`（`## static field AtEOF:bool = false` / `ContentDocument:Document | null` / `ContentText:string`）、`:1090-1093`（`StatementScanner.ContentDocument = document; StatementScanner.ContentText = document.GetRaw(0, document.GetCount());`）、`:206`（`if (code.length === 1 && !StatementScanner.AtEOF)`）、写入点 `statement-shape.xl.md:712`（`StatementScanner.AtEOF = true;`）。
