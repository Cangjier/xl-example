## 2. 根因（三条独立的「谁先看见那一格」）

### 2.1 族 T：函数 / 方法的返回类型 `(` 被当成参数表（3 条类型位 case 里的 2 条半）

`BracketRoleResolver.Classify` 对 `FunctionDeclarationShape` / `MethodDeclarationShape` 宿主的**每一只**
`(` 都回 `Known(ParameterList)`。返回类型里也会出现 `(`：

- `function f(): x is (string)` → `(string)`；
- `function f(): abstract new (a: number) => A` → `(a: number)`；
- `function f(): (string)` → `(string)`。

于是：

1. **角色目录**：这只 `(` 被装上参数表目录，`ParameterPossibleShape` 把类型里的 `string` / `a: number`
   收成 `ParameterShape`（`TypeBuilder.ParseParenthesizedType` 再报 `不支持的类型起点`）；
2. **族 hook 还有第二条路**：`FunctionDeclarationShape.OnBracketCreatedEvent` 对**任何** `(` 都调
   `OpenParameterList` —— `InstallIfSimple` 判 `(string)` / `(a: number)` 「像参数表」为真，于是登记
   `ParameterScan`、`PromoteName` 动名字格，收口格 `ComputePossibleShapes` 的
   `ParameterListPossibleShape.Finalize` 把里面的标识符收成 `ParameterShape`。
   这一条**与角色无关**：把角色改回 `Fallback` 之后 R10 仍然失败，就是它。

### 2.2 族 P：谓词的括号类型被当成调用实参（`gap-r956` 的第 4 行）

`const h = (x: unknown): x is (A | B) => true;` 里 `(A | B)` 的前一个代码单元是 `is`（一个 `Common`），
`IsCallCallee` 判真 ⇒ `Known(CallArgs)` ⇒ 括号里先垫出 `IdentifierShape` / `Symbol("|")`，
`ParseReturnType` 的谓词分支再读 `(A | B)` 时拿到的是形状 ⇒ `不支持的类型起点` ⇒ 上层 `箭头函数缺少 =>`。
`x is (` 在表达式里不成立（两个操作数相邻），所以这一格只可能是谓词类型。

### 2.3 族 B：类型体里的 `=> {` 被当成箭头块体（`type-fn-return-typeliteral` 的 interface 成员）

`interface I1 { m(cb: () => { a: number }): void }` 的 `{ a: number }` 前一个是 `=>`，
`BlockPossibleShape.OnChildBracketCreated` 走 `IsArrowUnit(previous)` 分支给它挂了块体语句目录。
挂上之后 `{ a: number }` 在 `:` 格被收成 `LabeledStatementShape`，`TypeBuilder` 再报
`不支持的对象类型成员`。它的父括号链是「方法形参表 `(`（Fallback，无目录）→ 接口成员列表 `{`
（`MemberList`，有目录）」——**类型体里不可能出现语句**。
（`type A1 = (opts: X) => { a: number }` 之所以本来就 ok：那只 `(` 是 `FunctionTypeParams`，有目录，
`OnChildBracketCreated` 的「宿主括号没目录」分支根本进不去。）

### 2.4 族 C：三目的分支位目录里没有箭头（`expr-ternary-arrow-branches`）

`ConditionalMemberPossibleShape` 在分支位只认「`Common` 操作数」与「值位 `{ … }`」。
箭头分支的首单元是 `(`（`flag ? (a: number) => …`）⇒ `Reject` ⇒ 候选全灭 ⇒
`CatalogGuide` 抛「没有候选形状可以构成（下标 3 = 分支那只 `(`）」。

## 3. 改动（4 个文件，+335 / −1）

### 3.1 `typescript/tokens/statements/bracket-role-resolver.xl.md`

1. **返回类型 `(` 让路**：`FunctionDeclarationShape` / `MethodDeclarationShape` 宿主上，只有
   `IsHeadParameterBracket`（`host.Data` 里**没有更早的 `(`**）才回 `Known(ParameterList)`，其余回
   `Fallback("return-type-position:" + TypeLiteral)` —— 与同表里 `FunctionDeclarationShape` 的 `{`
   分支、`IsElementPosition` 的 `:` 分支同一口径（返回类型归 `TypeBuilder`）。
2. **谓词括号让路**：新增 `IsTypePredicateIs(host, previous)`（`is` + 前面是名字单元 + 再往前第一个
   符号是 `:`），命中 ⇒ `Fallback("type-predicate-position")`，排在 `IsCallCallee` 之前。
3. **三目分支 `(` 保持 raw**：新增 `IsTernaryBranchMark`（前一个单元是还没建形状的 `Symbol("?")` /
   `Symbol(":")`），命中 ⇒ `Deferred(ArrowParams)`（只登记、不装目录）——与初始化器位
   `arrow-paren-wait-for-arrow` 同一条 Deferred 机制，箭头形参的 replay 仍由
   `ExpressionBuilder.ParseFunctionParameters` 在 legacy 建造里发生一次。

新方法两个：`IsHeadParameterBracket`、`IsTypePredicateIs`、`IsTernaryBranchMark`；全部只比结构位 / 符号文本。

### 3.2 `typescript/tokens/declarations/function-declaration-shape.xl.md`

`OpenParameterList` 开头加一道 `BracketRoleResolver.IsHeadParameterBracket` 闸门（§2.1 的第 2 条路）：
返回类型里的 `(` 连 `InstallIfSimple` / `PromoteName` / `ParameterScan` 都不碰。**这是 R10 那半条
必须单独修的原因**：角色目录让路之后，族 hook 的这条旁路还在建 `ParameterShape`。

### 3.3 `typescript/tokens/statements/block-possible-shape.xl.md`

新增 `EnclosedByTypeBody(unit)`：从宿主沿 `Parent` 往上找**最近一个带目录的括号**，角色是
`MemberList` / `TypeLiteral` ⇒ 类型体。`TryMountFunctionBody` 在 `arrow`（前一个单元是 `=>`）时先问这一句，
命中就不挂块体目录（`{` 保持 raw，收口格由 `TypeBuilder.ParseTypeLiteral` 整块读）。
值位的三族都不让路：语句壳箭头（父单元不是括号 / 最近目录括号是外层函数体）、成员方法体（前一个是 `)`）、
对象字面量里的箭头（最近目录括号是 `ObjectLiteral`）。

### 3.4 `typescript/tokens/expressions/forms/operator/conditional-possible-shape.xl.md`

**三目分支是箭头时不建树，整条交 legacy**（没有第二套箭头建造器）：

- 新增 `QuestionIndex` / `HasArrowBranch` / `ArrowFollowsQuestion`：
  `?` 之后出现 `=>` 符号单元（单调），或 `?` 之后的文档前瞻是 `( … )` 且再往后是 `=>`；
- `ConditionalPossibleShape.IsBuildable` 在 `HasArrowBranch` 时返回 `false` —— 候选**保持在场但不建**
  （`?` 那一格不建 ⇒ 整条三目留在 raw）；声明收口格
  `VariableDeclarationShape.FinishIncremental` 的 `builtShape === null` 分支本来就用
  `ExpressionBuilder.ParseExpression` 建整条 raw（与 legacy 同源、逐节点同树），所以不需要新动作；
- `ContinuationClaim` 在三目族命中时额外认领 `=>` 与 `:` 两格：这两格现在落在**声明层**，
  不认领就会被声明终结候选按 C10 抛 `declaration 符号 =>` / `符号 :`（实测：只放开 `IsBuildable`
  时首跳从「没有候选形状」变成「declaration 符号 =>」）。三目真的被建出来时这两格到不了声明层。

范围边界（有意）：判据只需要**中段**是箭头就能在 `?` 那一格判定，所以「只有右段是箭头」
（`flag ? 1 : () => 0`）仍走原来的建树路径（本轮不改）。目标 case 与最小片段的中段都是箭头。

   30 target + 5 smoke 全绿，实测未触发）。

## 7. 结论

四条 case 是**三条独立根因**，都不是箭头体本身：

1. **返回类型里的 `(` 被参数表族认领**（角色目录 + `OpenParameterList` 旁路两处）——一条判据
   「函数 / 方法自己的参数表永远是第一只 `(`」，清掉 `type-fn-return-typeliteral` 与
   `type-return-abstract-new`，并顺带关掉谓词括号在函数声明上的那一半；
2. **谓词 `is (` 被当调用**——一条「`is` 前面是名字 ⇒ 这是类型位」的让路，清掉
   `gap-r956-predicate-paren-type` 的箭头返回行；
3. **类型体里的 `=> {` 挂块体目录**——一条「最近目录括号是类型体 ⇒ 不让路」的判据，清掉
   `type-fn-return-typeliteral` 的 interface 成员；
4. **三目分支箭头**——不建树、整条交 legacy（复用既有 `builtShape === null` 收口通路），
   只补 `IsBuildable` 闸门与两格 `ContinuationClaim`，清掉 `expr-ternary-arrow-branches`。

30 target、5 smoke、1716 条 AST 指纹逐位不变。
