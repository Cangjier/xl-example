## 2. 触发位置（顺序）

```
Bracket.Transit:
  unit.Add(mounted) → mounted.Use(value).SignIn(index)
  → 宿主 OnBracketCreatedEvent
       ├─ ChildBracketCreatedHook（族收尾）
       └─ 旧窄触发：CatalogGuide !== null && EndPossible !== null && { && BracketCreatePossibleHook.Current === null
  → ChildBracketCreatedHook（宿主不是括号时）
  → BracketRoleHook.Current.OnBracketCreated      ← 角色目录在这里才装到新括号
  → **BracketCreatePossibleHook.Current.OnBracketCreatedPossible**   ← T2 新增
```

- 新括号自己的目录在 `OnBracketCreatedEvent` 时还是 `null`，所以新触发排在 `BracketRoleHook` **之后**；
- 钩子装了（开关开）时，`OnBracketCreatedEvent` 里的旧窄触发**不执行**，由新钩子接管，避免同一格两次；
- 触发实现：
  1. 新括号自己：`mounted.CatalogGuide !== null` 才问（`ComputePossibleShapes(context, BracketCreate)`）；此刻 `Data` 为空 ⇒ 返回 `Nothing`，不建形状、**不提前安装目录**；
  2. 父宿主：**严格沿用旧窄触发的安全判据**（`bracketStart === "{"` + `host instanceof Bracket` + `CatalogGuide !== null` + `EndPossible !== null`），只把来源换成 `BracketCreate`。
- 计数：`StatementRouteUtil.BracketCreatePossibleCount`（每只新括号）、`BracketCreateSelfCount`、`BracketCreateParentCount`。

**为什么父触发没有放宽字符集/宿主类型**：候选还不会按来源改变判据。实测放宽到 `(` / `[` 或非括号宿主，30 条 target 立刻出现 18 条 `SourceRange is not set` / `括号内没有表达式`（提前建出了宿主形状）。T2 的验收要求开关打开也逐字不变，所以触发范围保持旧窄触发的形状；放宽留给 T3/T5。

## 3. 双 build 守卫

`CatalogGuide` 新增：

- `LastBuildTokenIndex:int = -1`、`LastBuildDataLength:int = -1`：最近一次成功 `BuildByIndex` 的格与建完之后的 `Data.length`；
- 入口在 `token === undefined` 早退之后：两个字段与本次 `tokenIndex` / `host.Data.length` 都相等 ⇒ 直接返回 `Nothing`，并 `RepeatedCellSkipCount += 1`；
- 两个成功出口（终结候选 / 普通候选）在 `BuildByIndex` 之后写这两个字段，再 `Reset()`；
- **`Reset()` 不清这两个字段**：`Reset()` 是建完的正常收尾，清掉等于取消守卫；失效只由换格 / 换长度自然完成；
- 新增计数：`CatalogGuide.BuildCount`（成功 build 次数）、`CatalogGuide.RepeatedCellSkipCount`（守卫命中）。

## 4. 开关默认值

`StatementRouteUtil.EnableBracketCreatePossible:bool = false`。

关闭（默认）：`EnsureInstalled` 立即返回，`BracketCreatePossibleHook.Current === null`，`Transit` 只多一次 `null` 比较；旧窄触发仍是 T2 之前的行为。逐字节路径不变。
