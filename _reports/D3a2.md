## 1. 先钉死「为什么抛」：12 条失败格的 `Data`

`tmp/cells.mjs`（包 `VariableDeclarationEndPossibleShape.prototype.ComputeByIndex`，在抛出的那一格打印
`host.Data` 全表）与 `tmp/headshape.mjs`（打印链头形状的 `Data` / `Closed`）。12 条的失败格只有两种：

```
(A) 链头已经是复合形状，后面是 raw 后缀 / 类型尾：
    [IdentifierShape, =, CallExpressionShape, Bracket, Bracket, ., Common(b), !]     expr-assert-kernel-member-chain
    [IdentifierShape, =, IdentifierShape, String, ., Common(b), !]                  expr-r1215-tagged-template-nonnull

    [IdentifierShape, =, TypeOfExpressionShape, Bracket, Bracket, ., Common(v), +]   ex-round744-typeof-chain-in-binary

    [IdentifierShape, =, IdentifierShape, String, ., Common(length), +]             expr-template-tagged-in-operator
```

`Kind`（`member-chain-judge.xl.md:249`）要求 `=` 之后第一个代码单元是 `Common`，于是 (A) 一族里

既没有候选认领、`IsRawInitializer` 又为假（初始化器里已有形状）⇒ 兜底 `throw`。
这一层与 D3a §6 的交接判断一致，但**它不是全部**——见 §2。

## 2. 第二堵墙（D3a 交接里没写的那一半）

对这些单元一律抛 `不支持的表达式起点` —— `raw` 里必然带着那个已建形状。实测（`tmp/buildtest.mjs`，

## 3. 改动（3 个 `.xl.md`，纯插入）

### 3.1 `[D3a2:SHAPE-OPERAND]`（`expression-builder.xl.md` +32 行）

`ParsePrimary` 在兜底 `不支持的表达式起点` 之前加一条 `ShapeToken` 分支，按形状自己的生命周期分两支：

| 形状状态 | 处理 | 为什么 |
| --- | --- | --- |
| `Closed === false` 且有操作数子单元 | 把**后面的后缀链**接到那个操作数上，再整支交回（`ParsePostfixSuffix`） | 前缀运算符还在等操作数：`typeof o["f"]().v` 的树是 `typeof (o["f"]().v)`，不是 `(typeof o)["f"]().v`。实测这一支把 `ex-round744-typeof-chain-in-binary` 一次修好 |
| `Closed === true` | 直接当完整操作数，`ParsePostfixSuffix` 照常往外接 | `f()` / `a` / `!o` 都已经长完 |

**只影响「`Units` 里本来就有形状」的重建路径**：普通 legacy 解析的 `Units` 全是 basic token，
此前这两条分支的位置是 `不支持的表达式起点` 抛错，不是一条活路径。

### 3.2 新候选 `ShapeRootedTailPossibleShape`（`member-chain-judge.xl.md` +326 行）

**为什么不是「放宽 `Kind` 让 P1 的 `nonnull` 族接手」**：`Kind` 的族随**第一个**后缀单调落定
（该文件头的设计），而这一族的链是「已建形状 + 一串 raw 后缀」——`a["b"](d).b!` 的第一个后缀是
`(` / `[`（不是 `!`）。放宽 `Kind` 只会让 `member` / `element` 族在那些格上 `Accept`，而它们的
`IsBuildable` 又要求「链已长完」⇒ 多候选同格 `Accept` ⇒ `CatalogGuide` 永远 `Waiting`。
所以**单开一个候选，只认「链尾那个 `!`」**，它 `Accept` 的格子与 P1 六族零交集。

四个闸门（`ContinuationClaim` / `ComputeByIndex` / `IsBuildable` 读**同一份**判据，认领了就必须建得出来）：

1. `RootIndex`：`=` 之后第一个代码单元是**复合形状**（`ShapeToken` 且 `Data` 非空）；
2. `Continues(head)`：链头之后紧跟后缀续接（`` ` `` / `[` / `(` / `.` / `!` / `?.`）或 `as` / `satisfies`；
   `!=` / `!==` / `??` / 单独 `?` **明确不算**（实测 `let x = 1 != 2` 会退化成 `throw`）；
3. `IsTailCell`：当前格只可能由 legacy 重建来读（符号格 / `as`·`satisfies` / 后面还跟着后缀续接的单元）；
4. `IsBangTail`：当前单元是 `Symbol("!")` 且前一代码单元能承接后缀（`CanCarry`）。

`BuildByIndex` = `MemberChainJudge.Build` 的同一套惯用法（`raw` = `=` 之后到 `!`，`basePos` = `=` 的
`EndIndex`），读完不齐显式抛 `declaration 已建形状头的后缀未读完`（C10：宁可显式失败）。

### 3.3 注册（`expression-shape-catalog.xl.md` +2 行）

`// [E-CAT:FRAGMENTS]` 里 `NonNullPossibleShape` 之后一行 `ShapeRootedTailPossibleShape.AppendTo(shapes); // [D3a2]`。
`ExpressionContinuationCatalog.Claims` 因此自动包含它（同一个装配点，无需第二处接线）。

## 9. 交接（下一波若要继续这一族）

1. **先做决定，再动手**：变体 A 的 −37 / −11 说明 `FinishIncremental` 的「唯一根 + raw 尾巴」
   应该有一个「整段重建」出口（现在是 `D3a:ORPHAN-OPERATOR` 显式抛错）。这需要动
   `variable-declaration-shape`（D3a 的）或 `statement-route-util`（D3c/D3d 的），**本 WP 不碰**。
2. **`HasReducibleLeft` 读 `CanEndExpressionAt`** 是本族 `+` / `===` 的一半答案，但必须同时给
   `CanEndExpressionAt` 加「类型上下文（`as` / `satisfies` / `<` / `:` / `|` / `&` 之后）答 `false`」，
   否则 `as T & U` 会从 `throw` 漂移成错树。
3. **`!` 与语句层 `StatementEndPossibleShape` 同格 Accept** 是本族唯一一条「多候选」性质的崩溃，
   修点在语句层（`statement-end-possible-shape` / `ExpressionContinuationCatalog` 的调用方），不在成员链。
