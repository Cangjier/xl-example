## 3. 根因（一句话：EOF 收口漏了一次判定，不是「不会建」）

`declare function f(): void` 停在文件末尾时，逐字符 trace（`tshape-judge steps`）给出的终态是：

```
FunctionDeclarationShape pos=0 src=[0,36)
 ├ Common "declare"     ← 本该 DeclareKeywordShape
 ├ WrapSymbol " "
 ├ Common "function"
 ├ WrapSymbol " "
 ├ IdentifierShape "f"       ← 名字这一格是好的
 ├ Bracket [18,29)           ← 参数表：ParameterShape 都建了，但没交给 builder
 │  └ ParameterShape …
 ├ Symbol ":"
 ├ WrapSymbol " "
 ├ Common "void"        ← 本该 VoidKeywordShape
 └ WrapSymbol "\n"
```

即**外壳在 `function` 关键字那一格就挂出来了**（`FunctionDeclarationPossibleShape.BuildByIndex` →
`BodyGuideUtil.MountShell`，`Pos=0`），但壳的内部**整段留在 raw 单元**上。为什么：

1. 函数声明的壳把收口权**全部**交给终结候选 `FunctionDeclarationEndPossibleShape`
   （挂在壳的 `CatalogGuide.EndPossible` 上）。候选只在**壳自己的 `Data` 新增一格**时被问
   （`CatalogGuide.ComputePossibleShapesByIndex(host, host.Data.length - 1, context)`）。
2. `ComputeByIndex` 的四个 `Accept` 分支是：已闭合函数体 `{}` / 已闭合 `;` / ASI（下一行起一条
   **新声明**）/ `EndOfFileTokenShape`。
   `declare function f(): void` ⏎ 的末代码单元是 `void`，之后的换行只是 trivia；
   ASI 分支要求「下一行是 `StatementHeadWords` 里的词」，而下一行就是 EOF（`NextLineWord` 答 `""`）
   ⇒ `Reject`。**`;` 那一条分支就是这一步缺失的替身**——这也是「带 `;` 就全绿」的全部原因。
3. 第四分支 `EndOfFileTokenShape` 是**为这种形态写的**，但它永远轮不到：EOF 哨兵是
   `SourceFileShape` 的子单元（`SourceFileShape.Process` 里 `this.Add(eof)`），**不在壳的 `Data` 里**，
   壳永远等不到「`Data` 新增一格」。
4. 于是壳一路张着嘴走到 EOF，驱动层在 EOF 只做
   `mounted.TryToClose(context)`（`typescript/tokens/files/source-file-shape.xl.md:150-154`）——
   而 `FunctionDeclarationShape` **没有覆写 `TryToClose`**，走 `ShapeToken` 基类那一份：
   只补 `SourceRange.End`、只标 `Closed`，**一个节点都不建**。
5. 两处后果同源：内部节点全缺（`structural` 5–8），且 `SourceRange.End` 已被驱动层签到文件长度
   （含尾随换行）⇒ 建出来的 `FunctionDeclaration` 比 TS 的 `node.end` 多 1 字节
   （`0-26 vs 0-27` 的 `moved`，`[W5:EOF-TRIM]` 那一族治的正是这半）。

**为什么 `expr-generic-inst-statement.ts` 是绿的（R8 的反证被解释掉）**：
它的 `declare function` 后面还有 `f<string>;`，壳在下一行的首词那一格被 ASI 分支收掉，
**根本没走到 EOF**。所以那不是「另一个根因」，只是**没进这一格**。

**为什么 `declare const x: number`（同样无 `;`、同样在文件末尾）是绿的**：
变量族自己覆写了 `TryToClose`（`variable-statement-shape.xl.md:50`，由内向外关挂载链）；
`import-equals` / `export-assignment` / `namespace-export` 也各自有
`[W5:EOF-TRIM]` 的 `TryToClose`。**函数声明族是唯一漏掉这一条的无体声明族**——
这就是「同一格」的判据：缺口在族形状的 EOF 收口，不在 `declare` 关键字、不在参数表、不在返回类型。

## 4. 改动（1 个源页，1 个方法 + 1 个 import）

`typescript/tokens/declarations/function-declaration-shape.xl.md`

1. 新增 `## method TryToClose:(context:SyntaxContext)=>CloseStates`：
   - 先 `super.TryToClose(context)`（保留基类「补终点 + 标 Closed」的语义），
     只在**本次之前是开的**（`!this.Closed`）时继续；
   - 三个前提同时成立才动手：增量形状开关开 / 壳有 `CatalogGuide` 且 `EndPossible` 非空 /
     **`SourceRange.End >= document.GetCount()`**（= 本壳之后已经没有字符。中途的壳 `End` 一定
     小于文档长度，所以 `;` / 体闭合 / 中途换行三格逐字节走基类）；
   - 收口**不新写判据**：直接调终结候选自己的 `guide.EndPossible.BuildByIndex(this, …)`，
     也就是 `;` / ASI 那两格走的**同一批**建树函数（`FunctionDeclarationShape.FromUnits` +
     `BodyGuideUtil.FinishShell` + `DeclarationAsiBoundary.ReplayLeftover`）；
   - 文件末尾**没有尾随换行**时（`function f(): void` 直接 EOF），壳的末子单元就是末**代码**单元本身，
     而 `BuildByIndex` 会把「既不是 EOF 哨兵、也不是 `;` / 体括号」的末单元当成**下一条语句的开头**边界，
     于是把返回类型切在 `)` 之前。这里补一个 `EndOfFileTokenShape` 哨兵把「到这里就结束、没有边界单元」
     说清楚——这正是候选 `ComputeByIndex` 第四条分支的语义，只是那一格永远轮不到（§3 第 3 点）。
     哨兵随壳一起被 `FinishShell` 换掉，壳外无人认领；建不出来时撤掉它，`Data` 与进来时逐位相同；
   - `BuildByIndex` 抛错时**只**退回基类行为（= 修复前的现状），不吞成假绿、不假装建好。
2. 新增两个 import：`CloseStates`、`EndOfFileTokenShape`（后者无回边，不成环）。
