## 2. 根因（与 T8b 一致，本轮补上「为什么只有数字」）

`ExpressionShapeCatalog` 里的原子候选分两类：

- **有闸门**：`PrimaryAtomGuard.IsLoneAtom`（`StringLiteral` / `Template` / `Regex` / `BigInt` /
  `KeywordLiteral` / `This` / A1 `Identifier`）。后缀首字符 `.` `(` `[` 不在
  `PrimaryAtomGuard.ContinuationChars` 里 ⇒ `IsBuildable` 为假 ⇒ **不建形状**，初始化器保持 raw，
  收口格走 `VariableDeclarationShape.FinishIncremental` 的 `builtShape === null` 分支，
  由 legacy `ExpressionBuilder.ParseExpression` 整条建出 —— 这就是字符串 / 模板 / 正则今天
  已经不 fallback 的原因。
- **无闸门**：`NumericLiteralPossibleShape`（`IsBuildable` 未重写，默认 true）。数字在**数字那一格**
  就被物化成 `NumericLiteralShape`，之后 `.` / `?.` / `(` / `[` 到达时没有任何候选认领：
  - `.` 只在 `VariableDeclarationEndPossibleShape` 的 `text === "."` 分支被 `Reject`（等），
  - `(` 由 `ExpressionContinuationCatalog.Claims` 认领（等），
  - `[` 既不 raw（`IsRawInitializer` 为假）也不 `PreviousIsShape`（前一格是属性名 `toString`）⇒ 当场
    `throw declaration 括号`，
  - 收口格 `builtShape = NumericLiteralShape` 不是容器、也没登记身份 ⇒
    `[D1:SUFFIX-BRACKET]` / `[B4i:K1-CONTINUE]` 两道门都进不去 ⇒
    「有未并入的括号」/「根之外还有代码」。

一句话：**数字是唯一被提前物化、而物化之后没有 postfix 面认领的原子**；
`ExpressionBuilder.ParsePrimary` 也没有认它的分支（只有 `ControlHeadPossibleShape.IsAtom` /
`ExpressionAtomRegistry.Atoms` / `Containers` / `Nodes` 四张身份表）。

**判据 `1.` vs `1 .`**：完全由词法给出的单元划界，不另写字符判据——
`1.` 是**一个** `Common`（数字单元，含尾点），`1 .` 是 `Common("1")` + 空白 + `Symbol(".")`。
所以 `1 .toString` 的 raw 是 `[Common(1), Symbol(.), Common(toString)]`，
`1..toString()` 的 raw 是 `[Common("1."), Symbol(.), Common(toString), Bracket("("), …]`。
两种形态在收口格看到的「已建原子 + 后缀」完全同形，不需要按字符再分一次。

| 位置 | 新增 | 作用 |
|---|---|---|
| `Symbol` 分支（`text === "."` 之后） | `text === "?." && HasAtomInitializer(units)` ⇒ `Reject` | `1 ?.toString()` 的后缀格 |
| `Bracket` 分支（`PreviousIsShape` 之后） | `HasAtomInitializer(units) && FollowsMemberSegment(units, tokenIndex)` ⇒ `Reject` | `1 .toString[0]` 的下标格（链头是已建原子、前一格是属性名、再前一格是 `.`/`?.`/`!`） |
| `[D3a:RAW-INITIALIZER]` 的 defer 条件 | 追加 `HasAtomInitializer(units) && text === "!"` | 已建原子 + 后缀 `!`（`tag`x`.b!` 那一族） |

新增两个静态判据（都在本文件内，与既有 `HasContainerInitializer` / `PreviousIsShape` 同一套写法）：

- `HasAtomInitializer(units)`：`=` 之后有没有 `ExpressionAtomRegistry` 登记过的根（`Nodes` ∪ `Containers`）。
- `FollowsMemberSegment(units, tokenIndex)`：本括号的前一格是 `Common`、再前一格是 `.` / `?.` / `!`。

**为什么 `?.` 只认「前一格是已建原子」**：`CanDeferToAtomicInitializer` 对 `?.` / `??` 有既有显式
拒绝账本（`throw/composite/class-ball`、`throw/composite/expression-zoo` 依赖它们保持抛错）。
`const a = b?.c` 的 `b` 被 `PrimaryAtomGuard` 挡住、根本没有形状落地 ⇒ `HasAtomInitializer` 为假，
账本一个字节不改（`expr-r1214-optional-call-then-suffix.ts` 仍 fallback，实测）。

**为什么 defer 只加 `text === "!"`**：先按「已建原子 + 任何 `CanDeferToAtomicInitializer` 符号」放行过，
`expr-template-tagged-in-operator.ts`（``tag`x` + y``）当场变成**静默错树**——
判据 `status=diff`，`TaggedTemplateExpression` 区间 `178-206` vs `178-190`（标签模板链被重排）。
所以收窄成「后缀面在这条分支上只剩 `!`」（`.` / `?.` 各有自己的分支，`(` / `[` 走 `Bracket` 分支），
二元运算符一律不 defer：宁可显式失败、由文件级 legacy 给正确树（C10）。

## 4. 为什么这不是「把 raw 整段交给 ExpressionBuilder 重建」

收口格复用的是**既有** `[B4i:K1-CONTINUE]` 分支（T8 之前为容器 / R15 标签模板就存在的那条）：

1. `ExpressionBuilder.ParsePrimary` 的 `HasNode` 分支把**已建原子原样返回**——不重建、不重算 `Pos`；
2. 后缀由 `ExpressionBuilder.ParsePostfixSuffix` 接上（与 legacy 唯一实现同一份代码）；
3. 收口前先验「整段读完」（`builder.At !== Units.length` 显式抛「初始化器未读完」），
   再按源区间验覆盖（首格 … 末格），覆盖不齐显式抛「容器被截断」。

T8c §3 那种错树的成因是「形状的源码区间不在 raw 里」（形参 `(` 已被消费）；
数字原子的 `Common` 单元**整格被 `Replace` 成形状**、区间与 raw 逐字节重合，
所以 `ParsePrimary` 消费它时没有任何信息丢失。**实测证明**：3 条被修文件改前（legacy 兜底）
与改后（增量路径）的 AST 指纹**逐条相同**（见 §5 的 `astChanged=0`）——
增量树与 legacy 树是同一棵树，不是一个「看起来差不多」的树。

## 7. 遗留

1. **`?.` 只对「已建原子」开放**（`HasAtomInitializer`）。raw 初始化器上的 `?.`（`const q = a?.(d).b(d)`，
   `expr-r1214-optional-call-then-suffix.ts`）仍按既有账本显式失败——那是 C10 的显式拒绝面，
   不在 A3 边界内，需要单独一轮连同 `Nothing` 语义一起处理。
2. **已建原子 + 二元运算符**仍是 fallback（``tag`x` + y`` 一族）。这一族在收口格重建会重排标签模板链
   （实测 `status=diff`），正确修法在标签模板的续接面，本轮按 C10 保留显式失败。
3. `expr-tagged-template-bang-suffix.ts`（``a`x`!(d)``）与 `expr-template-tagged-suffix.ts`
   （``tag`abc`.length``）仍 fallback：它们的首跳不是同一个「后缀格」（`!(d)` 的前缀/后缀歧义、
   标签模板后的成员链另有一套判据），本轮未动。
4. `PrimaryAtomGuard` 的续接白名单文档里 `.` `(` `[` 那一行仍写着「A3 的 postfix 候选尚未合并」——
   对**标识符**候选而言该判据确实没变（所以本轮一个字没改），但数字已经走 `Nodes` 这条路，
   下一轮整理文档时应把这行改成「原子候选按 `IsLoneAtom` 让位、已物化原子走 `Nodes` 身份表」。
5. `fallback=57` 里 A 类只剩 `stmt-switch-nested.ts`（`不支持的表达式起点`）与
   `lex-preprocessor-if.ts`（`表达式没有读完`）两条，与 A3 关系不大。
