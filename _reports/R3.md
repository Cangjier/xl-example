## 1. 根因：`Pos` 是一只手的口径，`host` 不在里面

`if (\n  a &&\n  b\n) {…}` 的逐字 trace（`tmp/tshape-judge/diff-if/trace.md`）里，`a` 在 step 8
（把 `a` 关掉的那个空白格）就建成了 `IdentifierShape`，`b` 在 step 15 建成，两者形状本身都对。
差别只在 `Pos`：

| 单元 | 之前的 `pos` | TS 的 `pos` | 前一个 token |
| --- | ---: | ---: | --- |
| `a` | 7 | **4** | `(`（`[3,4)`）——但它在**括号的 `Data` 之外** |
| `b` | 11 | 11 | `&&`（`[9,11)`） |

`ControlHeadPossibleShape.PosAt(units, tokenIndex)` 只看 `units`（= `host.Data`）：从 `tokenIndex-1`
往前跳过 trivia 找第一个 code 单元，**找不到就退回 `units[tokenIndex].SourceRange.Start`**。
括号里第一格前面只有 `WrapSymbol [4,7)`（`\n  `），一个 code 单元都没有，于是退到 `a` 自己的
`Start` = 7。而 TS 的 `pos` 是「full start」= 上一个 token 一结束的位置，那个 token 是**括号的开启符**
`(`，它属于 `host` 而不属于 `host.Data`。

`src` 一直是对的（`[7,8)`，由 `IdentifierShape.FromBasicToken` 从 basic 单元照抄），
本类**不碰** `src`。

## 2. 改法：一份通用口径 `ShapePosition`

新文件 `typescript/tokens/positions/shape-position.xl.md`（类型页放 `typescript/tokens/` 下，
和它服务的 `*.xl.md` 形状/候选同层；core 里没有 `Bracket` 之外的依赖，但 `Pos` 是 TS AST 的
口径，不是语法层的东西，所以不进 `core/syntax`）：

```ts
static PosAt(host: Token, units: Array<Token>, index: int): int
```

1. 从 `index - 1` 往前跳过 `IsTriviaToken`，**第一个 code 单元** ⇒ 返回它的 `SourceRange.End`；
   `End` 还没签出（`< 0`）就继续往前找。
2. 一个 code 单元都没有：
   - `host instanceof Bracket` ⇒ `host.SourceRange.Start + 1`（**开启符 End**）；
   - 其它宿主（`StatementShape` / 各类 `DeclarationShape` / `SourceFileShape`）⇒ `host.SourceRange.Start`，
     宿主自己还没签入就 `0`。

**关于「开启符 End」**：`Bracket.SourceRange` 是**整只括号**的区间——还没闭合时 `End = -1`，
闭合后是闭合符之后（`src=[3,17)`）。所以「开启符 End」不能读 `host.SourceRange.End`，只能由
`host.SourceRange.Start`（开启符自身的下标）`+ 1` 得到；开启符恒为一个字符，`(` / `[` / `{` 都成立。
这一条写进了类注释，避免下一个人再按字面读 `End`。

### 为什么是通用规则而不是给 `if` 打补丁

「`pos` = 上一个 token 的结束」对**所有** TS 节点成立，括号里第一格只是它最容易被漏掉的情形：
前一个 token 在父容器的 `Data` 之外。同一套推理给出了 `ExpressionBracketPossibleShape.PosAt`
原有的算法（从开启符 +1 往后逐格走、每遇到非 trivia 就记一次 `End`）——两者对同一个下标必然同答案，
所以那份也被收敛进来了（见 §3）。控制流头只是**唯一**在旧实现里退到「自己的 `Start`」的那一处。

## 3. 迁移台账

| 站点 | 处置 |
| --- | --- |
| `ControlHeadPossibleShape.PosAt` | 改走 `ShapePosition.PosAt(host, host.Data, tokenIndex)`；`host` 从 `BuildByIndex` 传入 |
| `ExpressionBracketPossibleShape.PosAt(bracket, units, tokenIndex)` | 改成 `return ShapePosition.PosAt(bracket, units, tokenIndex)`（签名留壳，四个调用点不动） |
| `NamedImportsPossibleShape.BuildByIndex` | 删掉手抄的 12 行循环，改走 `ShapePosition.PosAt(host, host.Data, index)` |
| `NamedExportsPossibleShape.BuildByIndex` | 同上 |
| `ObjectBindingPatternPossibleShape.BuildByIndex` | 同上 |
| `ImportAttributesPossibleShape.BuildByIndex` | 同上，但下标传 `at`（关键字 `with`/`assert` 那一格），不是括号那一格 |
| `ParameterListPossibleShape.PreviousParamPos` | **保留**：顺序是「先壳、后 `Data`」——`...` / `:` 已被吃进壳、不在 `Data` 里，只看 `Data` 会退成逗号的 End（R1 修过的那条漂移）。它的括号 fallback 本来也是 `Start + 1`，与新规则一致 |
| `IncrementalItemPosition.AfterPreviousCode` | **保留**：没有 `host` 形参，fallback 固定 `0`；调用点宿主都是变量 / 二元 / 右操作数这类从 0 开始的形状，`0` 与 `host.Start` 同值。要改得动五个调用面，收益为 0 |
| `BodyGuideUtil.BasePos` / `MemberShellCatalog` / `StatementBuilder` 的 `Positions[…]` | **保留**：那是 legacy `ExpressionBuilder.Positions` 的同一口径镜像（rule 4），必须与 legacy 逐字节相同 |
| `AbstractKeywordShape` / `DeclareKeywordShape` / `ExportKeywordShape` 的 `FromBasicToken` | **保留**：那里填的是占位，宿主随后按含前导 trivia 的口径覆盖 |

净效果：6 个文件 `-103 / +39` 行，`Pos` 的计算点从一个「谁知道谁自己抄一份」变成一处。

## 4. 建格时机：不需要改，已在最早的一格

交接里写的是「`a` 到 step 14 才成 `IdentifierShape`」。实测（`tshape-judge trace`，
`trace.md` 的「首见形状」表）是 **step 8**：

```
| IdentifierShape | 8 | " " |
```

也就是 `a` 这个 `Common` **被关上**的那一格（下一个字符 `" "` 到达、`Common` 关闭时才问目录），
这是 `CatalogGuide` 「basic token 关闭时问一格」的机制本身，不是延迟。step 7（`a` 刚出炉）时它
还是 `Common`，因为字符流里没有「`a` 后面还有没有标识符字符」的信息；要更早只能在扫描器上做
前瞻，属于另一层。所以**时序不是缺陷，本次不改**，也没有残项。
