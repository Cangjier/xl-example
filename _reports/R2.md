## 1. 根因

`tmp/diff-bigint.ts` = `const b = 0b1010/*c*/ / 1_000 / 10n;`。逐字 trace
（`tmp/tshape-judge/diff-bigint/trace.md`）：

- step 20（块注释收尾）：`0b1010` 已经在关闭格上建成 `NumericLiteralShape src=[10,16)`；
- step 22（第一个 `/` 字符）：`/` 先按 `Symbol` 收下（`RegexToken.Transit` 对 `value === "/"` 一定 Undo）；
- step 23（`/` 后那个空格）：`RegexToken.Transit` 被判据放行，`/` 被撤回并原地换成
  `RegexToken src=[22,…)`，` / 1_000 /` 整段被吃进正则，EOF 处声明在注释位置收口。

放行来自 `RegexTemplate.CanStart` 的这条默认判据：

```ts
if (!lastCode.IsBasicToken) {
  return true;   // 「不是 basic token ⇒ 语句边界 ⇒ 起正则」
}
```

它对**语句形状**成立，对**已建操作数形状**不成立：`NumericLiteralShape` /
`BinaryExpressionShape` / `CallExpressionShape` / 容器 / 关键字叶子都是**已结束的操作数**，
后面那个 `/` 只能是除号。注释只是让「操作数在 `/` 之前就已经建成本地形状」这件事**提前**发生：
没有注释时同样的 bug 出现在**第二个** `/` 上（`const z = x / 2 / 3;` 基线也是
`BinaryExpression-1 / SlashToken-1 / NumericLiteral-1`）。所以这不是「只修注释」的问题。

## 2. 改法：一条判据链，除号优先

`typescript/run/typescript-template.xl.md` 的 `CanStartAt` 重排为：

1. `slashIndex = SlashIndex(...)`、`lastIndex = PreviousCodeIndex(slashIndex - 1)`；
   **在 `super` 之前**问 `this.CanEndOperand(units, lastIndex, slashIndex)`：能结束表达式 ⇒ **除号**，直接 `false`；
2. 判不出来才走 `super.CanStartAt`（词法默认：文件开头 / 语句形状边界 / 表达式关键字 ⇒ 正则）；
3. 再走位置判据：控制头 `)` / `else`·`do` / 块语句尾 `}` / 箭头体 `}`+换行 ⇒ 正则。

新增/抽出的判据：

- `CanEndOperand(units, unitIndex, slashIndex)`：按 token 类型分派，不按「前一个是谁」分派。
  - `String` / `RegexToken`（字符串、模板、正则字面量）⇒ 操作数；
  - `Bracket`：`)` = 非控制头（控制头见 `IsControlHeadTail`）；`]` ⇒ 操作数；
    `}` = 非块语句尾、非箭头体（`IsStatementBraceTail` / `IsArrowBodyTail`）；
  - `Common`：`ExpressionKeywords` 之外一律操作数——标识符、数字（含 BigInt `n` / 分隔符 `_`）、
    `this` / `super` / `true` / `false` / `null`；
  - `Symbol`：只有**后缀** `++` / `--`（按再前一个实义单元判前缀 / 后缀），其余符号 ⇒ 非操作数；
  - 非 basic token：`IsOperandShape` 为真 ⇒ 操作数；语句形状 ⇒ 交回 `super`。
- `IsOperandShape(unit)`：`ExpressionAtomRegistry.HasContainer`（四种容器身份表）
  ∪ `…ExpressionShape` ∪ `…LiteralShape` ∪ `IdentifierShape` / `PrivateIdentifierShape`。
  语句形状（`…StatementShape` / `BlockShape` / `TryStatementShape` / `CatchClauseShape`…）与
  `…PossibleShape` 不在表内。名字判据在本仓有先例（`RightOperandPossibleShape.IsOperatorLike`
  就是 `name.endsWith("TokenShape")`）。
- `IsControlHeadTail(units, bracketIndex)`：从 `CanStartAt` 里抽出的
  `if`/`while`/`for`/`with` 判据（`obj.if(a)` 的 `)` 不算，因为 `(` 前那个词之前是 `.` / `?.`），
  `CanEndOperand` 与位置判据共用。
- `IsArrowBodyTail(units, braceIndex, slashIndex)`：从 `CanStartAt` 抽出的
  「`=>` 体的 `}` + 到 `/` 之间有换行」判据，同样两处共用。

**trivia 不分叉**：四条新判据都经 `PreviousCodeIndex` 取实义单元，`/* */`（`AreaAnnotation`）、
`//`（`LineAnnotation`）、空白与换行（`WrapSymbol`）走的是同一条路，没有「注释专用分支」。

**保留的例外**（回归网钉住）：控制头 `)` 后正则、`else` / `do` 后正则、块语句尾 `}` 后正则、
箭头体 `}` 换行后正则、`obj.if(a) / 2` 仍是除号、`({a:1}) / 2` / `[1,2] / 2` / `f() / 2` 仍是除号。

## 3. 顺带修掉的两个「暴露出来的」缺陷

修好除号判定后，`diff-bigint` 的右半段第一次真的被解析，于是暴露出两个**先于本次改动就存在**的
叶子归类缺口（无 `/` 也能复现）。不修它们，`tshape-judge ts tmp/diff-bigint.ts` 到不了 `ok`：

1. **BigInt 当二元右操作数**：`const b = 1 + 10n;` 基线产出 `IdentifierShape text="10n"`
   （TS 是 `BigIntLiteral`）。`RightOperandPossibleShape.ComputeByIndex` 只认 `IsNumber()`，
   `BuildByIndex` 因此落到标识符分支。已补 `IsBigInt()` 与 `BigIntLiteralShape`。
   顺带：`BinaryOperatorPossibleShape.Operand`（左操作数物化）同样补了 BigInt。
2. **关键字字面量当二元左操作数**：`const u = this / 2;` 基线产出 `IdentifierShape text="this"`
   （TS 是 `ThisKeyword`）。`this * 2` 走 `ReassociationPossibleShape` 所以没事，`/` 走
   `BinaryOperatorPossibleShape.Operand`，那里把任何 `Common` 都当标识符。已补
   `this` / `super` / `true` / `false` / `null` 五个关键字形状。

两处都是「补一格已有的形状工厂」，没有新语法口径；wide-ast 差异 29 → 26 即由此而来。

## 5. 已知未修（与本次判据无关，基线同样失败）

`if (/re/.test(s)) { }`：`tshape-judge` 报 `incremental-error`，步 20（块体收尾）抛出。
trace 里树其实是对的（`RegexToken src=[4,8)` 在控制头括号内），失败在**块体收口**那一层，
不是 `/` 的起点判定；基线同一份也是 `incremental-error`。最小复现：

```ts
if (/re/.test(x)) { }
```

`if (x) { }` / `if (a) /re/.test(s);`（无块体）都 ok，说明卡在「控制头括号里含 `RegexToken`
+ 后面接块体」这条既有组合上。本次没有动它（超出「`/` 判定」的边界，且属于控制头 / 块体建造层）。
