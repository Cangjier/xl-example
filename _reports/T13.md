## 4. 未达项：fallback 46 没有降到 45（如实上报，未硬修）

本行登记**只影响「声明初始化器的根是 `new` 形状 + 后面还有后缀」这一格**。实测语域里不存在这种文件：

- 1716 条里所有 `new X(...)` 之后带 `.` / `[` / `!` / `(` 的行都在**表达式语句**里
  （`new A().b;`、`console.log(new C().x + new C().m());`、`new C().b?.(1);` …），这些条目**改前就 ok**，
  登记与否不影响（0 条首跳/指纹变化已证明）；
- 唯一「声明里 `new` + 后缀」的 `const g = new A.B`abc`.c;`（`expr-template-tagged-suffix.ts` L13）改前就 ok
  （根不是 `NewExpressionShape`，走标签模板链）；该文件整体 fallback 来自 L11/L12 的
  `const f = o.` ⏎ `tag`abc`.length;`（ASI），与本轮无关；
- 剩下 3 条 `new` 族 fallback 的首跳都在**建树格之前**，属另一个缺口，本轮按「不改其它判据」不碰：
  `ex-new-variants.ts` → `const d = new (getCtor())();`；`expr-new-callee-postfix-assert.ts` →
  `const n8 = new (a!.b)();`；`expr-new-comment-callee.ts` → `const c = new /* c */ (A)(2);`
  三者的首跳都是 `expression new 关键字`（`new` 与 `(` 之间的被构造者解析）。

因此「fallback 46 → ≤45」这条**本轮未达成**（46 → 46），但**case 本身已修**（judge ok、无 fallback），
且没有回归、没有 30 target 变化、1716 指纹 0 变化。按任务约定（「不硬修」）保留这一行改动并上报。

## 6. 结论

`NewExpressionShape` 与 `CallExpressionShape` 同构，缺的确实只是「建完登记身份」这一行：
`ExpressionAtomRegistry.RegisterNode(shape)` 之后 `new A(1).b(2)` 走既有的「根 + 根之后还有代码」分支，
`ParsePrimary` 用 `HasNode` 收下已建的 `NewExpressionShape`（不重建、不重算 `Pos`），`.b(2)` 由 legacy
`ParsePostfixSuffix` 接上，增量树与 TS 逐字一致（`(new A(1)).b(2)`）。

代价面：语域 1716 条指纹 0 变化、fallback 标记 0 变化、首跳 0 变化；30 target / 5 smoke 不变。
收益面：`new` 族 18 条矩阵 **11 FALLBACK → 1**（只剩既有的 `!` 面），且都经 judge 与 TS 对齐。
只是这 10 条形态在 1716 条语域里**没有对应文件**，所以语域 fallback 计数不动（46 → 46）。下一轮若要收
语域 `fallback`，入口是 `new (…)` 括号被构造者（三条例子的首跳），不是本行。
