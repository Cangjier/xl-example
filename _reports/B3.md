## 0. 一句话结论

控制流头的 `(` 现在**在创建格就装上了 `ControlHead` 目录**（`WaitingEndPossible` + 一个头候选
`ControlHeadPossibleShape`），头里的标识符 / 数字字面量**在各自的 token 关闭格**就地建成
`IdentifierShape` / `NumericLiteralShape`，` )` 那一格补判最后一格（`switch (a)` 的 `a`）——
`if (` / `for (` / `while (` / `switch (` / `with (` 五处同一条通道。

**收口零回归**：`ts-all` = 429 / **426 ok** / 3 err（与基线同一组 3 条，`error step` 不提前）、
`structural 0` / `fields 0` / `moved 0`；`tts` exit 0；gates **4 PASS / 0 FAIL / 7 N/A**，
wide-ast 档位仍是登记在案的 **5 崩溃 / 32 差异 / 94 fallback**（不恶化）。

`{` 侧（catch / finally / 方法体 / import-export）**本轮未交付**，原因与最小复现见 §4：
A1 矩阵把这四个 site 判成 **Deferred（宿主壳在括号创建时还不存在）**，要让它们变 Known 必须
「先建壳」——那正是任务书明令禁止的「新增建树路径」。

## 5. 风险与遗留

1. `Bracket.Close` 多了一次「补判最后一格」，受 `CatalogGuide.FlushOnClose` 门控（默认 `false`）。
   本分支里只有 `ControlHead` 目录置真；`ParameterList`（B1）/块体 / 函数体 / 声明体都不受影响。
   若将来有角色要复用，只需在自己的 `BracketRoleCatalog` 上置 `FlushOnClose = true`。
2. `ControlHeadPossibleShape.Atoms` 是进程内静态表，`SourceFileShape` 构造器**每文件清空**；
   `ts-all` 一次跑 429 个文件未观察到增长问题。
3. `EnableControlHeadCatalog = true` 让 B0 总闸从「第一个函数形参括号」提前到「每个文件第一只括号」：
   多出来的角色解析对族已装目录的括号是 `AlreadyInstalled` + `SetEndPossible(null)`（零改动），
   没有目录的只计数。`ts-all` 的 429 条逐条读数证明这一步本身不改产物。
4. 未做的是 `deferred-bracket-catalog.Bind` 的调用点（B2 的建壳点），所以 Deferred 条目目前
   只登记不唤醒——`Report()` 里 `pending > 0 / replayed == 0`，这是**预期**读数，不是缺陷。
