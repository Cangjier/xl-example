## 0. 一句话结论

**任务书里「类声明前有修饰符」的描述与用例原文不符**：两条用例是**类成员**的修饰词链——

```
gap-sweep-linecomment-clsmod-01.ts : class C { public static //c⏎readonly a = 1; private m() { } }
gap-sweep-newline-clsmod-01.ts     : class C { public static ⏎readonly a = 1; private m() { } }
```

首跳不在 `export` / `declare` / `abstract` 与 `class` 之间（那四格在矩阵里本来就是 `ok`），而在
**成员外壳收口时 `MemberBoundary.FindMemberBoundary` 把 `static` 之后的换行判成了成员边界**：
`static` 走 TS 的 `nextTokenCanFollowModifier()`（**不看换行**，`get`/`set` 也属不看换行那一档，
但它们是合法类型名，见 §3），换行后仍是同一条成员的修饰词链。

## 1. 首跳的直接证据

修复前 `tshape-judge steps`（`tmp/tshape-judge/gap-sweep-linecomment-clsmod-01/trace.md`）：

```
| PropertyDeclarationShape | 187 | " " |      ← `a` 闭合时早建外壳，壳内已有 public static / readonly a
| PublicKeywordShape       | 189 | " " |      ← 下一格 `=` 一进来就收口成「public + 名字 static」
| IdentifierShape          | 189 | " " |
| ReadonlyKeywordShape     | 192 | " " |      ← 剩下的 `readonly a = 1` 变成第二条成员
```

`tmp/r14-dump.mjs` 同时给出两侧终态（修复前）：

```
TS PropertyDeclaration [158,192) " public static //c readonly a = 1;"
   PublicKeyword / StaticKeyword / ReadonlyKeyword / Identifier(a) / 1
CJ PropertyDeclaration [158,172) " public static"      ← 名字是 static（Identifier），静态修饰词丢了
   PublicKeyword + Identifier(static)
CJ PropertyDeclaration [172,192) " //c readonly a = 1;" ← 第二条成员
```

即 #14/#15 记的 `Identifier+1 PropertyDeclaration+1 StaticKeyword-1` 精确对应：
`static` 被当成**名字**（Identifier+1、StaticKeyword−1），整条成员被劈成两条（PropertyDeclaration+1）。

## 2. 根因（两处，同一个语义）

`typescript/tokens/types/member-boundary.xl.md` · `FindMemberBoundary`：

```ts
if (!HasLineBreakBetween(code[at - 1], code[at])) continue;
if (!CanEndTypeUnit(code[at - 1])) continue;
if (IsInitializerIndexContinuation(code, at)) continue;
if (!LooksLikeMemberStart(code, at)) continue;
return at;                            // ← 上一格是 `static` 也照切
```

`class-member-possible-util.Analyze` 本来有一条护栏（`complete && IsModifierWord(code[end])` ⇒ 不收口），
但**成员外壳的收口走的是 `member-shell-catalog.FinalizeShell` → `FindMemberBoundary`，没有这条护栏**，
于是早建外壳在 `static` 这一格把自己切断了。

第二处（同族、**既存**缺陷）：`member-shell-catalog.OpenNextHead` 在边界收口后只抢**边界那一格**
（`Create(host, at, at)`）。可 `FinalizeShell` 是**触发收口的那一格已经进壳之后**才跑的，边界尾巴可能不止一格：
`class C { static ⏎ readonly ⏎ a = 1 }`（TS：字段 `static readonly` + 字段 `a = 1`）里 `=` 已经在壳里，
只抢 `a` 会把 `=` 留在宿主上 → 正品少了初始化器 → legacy 侧抛「类成员之间缺少分隔符」
（该 crash 在 `57357c34` 上就存在，不是本趟引入，见 §6 第 3 条）。

## 3. 改动（2 个源页：改 2 条判据 + 新增 2 个判据 + 2 处表达式）

| 文件 | 改动 |
|---|---|
| `typescript/tokens/types/member-boundary.xl.md` | `FindMemberBoundary`：`CanEndTypeUnit` 之后新增一格——上一格是 `IsLineBreakInsensitiveModifier`（只认 `static`）且下一格 `CanFollowModifierToken` ⇒ **不是边界**，继续往后扫；新增两个 static 判据（`IsLineBreakInsensitiveModifier`、`CanFollowModifierToken`，后者与 `ClassDeclarationShape.CanFollowModifier` 同口径，放这里是为了不产生 `member-boundary → class-declaration-shape` 的环） |
| `typescript/tokens/types/member-shell-catalog.xl.md` | `OpenNextHead`：`Create(host, at, at)` → `Create(host, at, host.Data.length - 1)`，边界之后**已扫过的尾巴整体**交给新外壳（并补了为什么尾巴可能不止一格的说明） |

为什么只认 `static`、不认 `get`/`set`：TS 里 `get`/`set` 同样不看换行，但它们**是合法类型名/成员名**
（`a: get` ⏎ `b: number` 是两条成员、`class C { readonly = 1 }` 的 `readonly` 是名字），光凭相邻两格分不出来，
所以保持原判据；`static` 是保留字，不可能自己当类型名，`static = 1` 这种「下一格接不上修饰」由
`CanFollowModifierToken` 否掉。**没有为两条用例写特判，也没有退回 legacy**；`ScanTypeMemberBoundary` /
`FindTypeMemberBoundary`（interface / 类型字面量侧，`static` 在那里是 TS 非法）未动。

## 6. 遗留与边界

1. `get` / `set` 的跨行修饰词链（`class C { get ⏎ x() {} }`）**没动**：它需要区分「访问器关键字」与「类型名 / 名字」，
   不是相邻两格能判的；矩阵里 `get ⏎x()` / `set ⏎x()` 现在是 ok（走 legacy 正品），所以不改也不回归。
2. `ScanTypeMemberBoundary` / `FindTypeMemberBoundary` 保持原判据：`static` 在 interface / 类型字面量里是 TS 非法，
   语料（wide-ast 跳过 TS 非法 11 件）不覆盖；等真有合法形态再谈。
3. 本趟顺带修掉的 `class C { static readonly⏎a = 1 }` 一族 crash 是**既存缺陷**（`57357c34` 上同一条用例同样抛
   「类成员之间缺少分隔符」），不在语料里；修它是因为它与目标是**同一个判据的收尾**（边界之后已扫过的尾巴）。
4. 未做：`statement-scanner` 未改——两条用例的首跳根本不在语句分派层，改它只会扩大面。
