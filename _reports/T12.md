## 2. 根因（两条独立的「谁先看见那一格」）

### 2.1 族 C：调用形状不是收口格认的操作数（H1/H2/H6/H7 + 1 条既有 case）

`f("y")` 在 `)` 关闭格由 `CallPossibleShape.BuildByIndex` 建成 `CallExpressionShape`，
**但没有登记身份**。收口格 `VariableDeclarationShape.FinishIncremental` 的两道闸门都按
`ExpressionAtomRegistry.HasContainer / HasNode` 判「根之后还剩什么」：

- `f("y").x` / `f("y").then`（无调用）⇒ `根之外还有代码`；
- `f("y").then(r => r)` / `f("y")[0]` / `f(1).b`x`` ⇒ `初始化器有未并入的括号`
  （那只 `(` 整只落在根区间**之后**，但根没登记过身份，后缀让路分支进不去）。

对照：`arr.map(...)`（链头是 `Common`，整条由 `MemberChainJudge` 建）与 `(f()).then(...)`
（括号容器登记过 `Containers`）都 ok —— 缺口恰好是「增量候选自己建出的调用形状」。

### 2.2 族 T2：三目的判据只看中段（右段箭头 / 字面量分支）

`ConditionalPossibleShape` 的 `IsBuildable` 在 `?` 那一格决定「建不建树」，判据 T11 只覆盖
**中段**（`?` 之后的前瞻就是 `(`）。而 `ConditionalMemberPossibleShape` 的两个分支位只认
`Common` 操作数与值位 `{ … }`：

| 形态 | 分支头 | 那一格 |
|---|---|---|
| `flag ? 1 : () => 0` | 右段 `(` | `Reject` ⇒ 候选全灭 ⇒ 下标 5 |
| `flag ? 1 : x => x` | 右段词 + `=>` | `?` 建树 ⇒ 右段 `x` 收成 `IdentifierShape` ⇒ `declaration 符号 =>` |
| `x ? "t" : "f"` | 中段 `"` | `Reject` ⇒ 下标 3 |
| `a ? b : 'x'`（r1242） | 右段 `'` | `Reject` ⇒ 下标 5 |

r1242 的「标签面」在此分支上其实**已经全绿**（`lbl1: 'x'` / `lbl2: \`x\`` / `lbl3: (x)` /
`lbl5: -1` / `lbl6: !x` / 七个体宿主 / 值位 / 类型位逐条实测 ok）；文件唯一失守的是
`const r = a ? b : 'x';` 这一行（`tmp/t12-r1242.txt` 12 条逐条二分）。

## 3. 改动（2 个文件，+270 / −9）

### 3.1 `typescript/tokens/expressions/forms/postfix/call-possible-shape.xl.md`

`BuildByIndex` 建完 `CallExpressionShape` 之后加一行 `ExpressionAtomRegistry.RegisterNode(shape)`
（`+1` 行实现 + 注释/文档）。与 [T9] 数字原子、[R15] 标签模板链**同一条** postfix 通路：
收口格走「根 + 根之后还有代码」分支，`ExpressionBuilder.ParsePrimary` 用 `HasNode` 把这个已建形状
当操作数收下（不重建、不重算 `Pos`），`.` / `?.` / `!` / `(` / `[` / 模板由
`ParsePostfixSuffix` 接上。

只登记 `BuildByIndex` 这一处（增量候选自己的建树点），不登记 `ParseBracketArguments` 一侧：
那一条只建实参、不建调用形状（与 [T9]「只登记声明初始化器的根原子」同一口径）。

### 3.2 `typescript/tokens/expressions/forms/operator/conditional-possible-shape.xl.md`

`IsBuildable` 的闸门从 `HasArrowBranch` 换成 `HasLegacyBranch` = `HasArrowBranch` +
`UnbuildableBranchHead`。新增 4 个静态方法：

- `UnbuildableBranchHead(question)`：从 `?` 起字符扫描，**中段头**与「深度 0 的第一个 `:`」
  之后的**右段头**分别判一次；头是引号 ⇒ 让路，头是 `(` 且 `ParenArrowAt` ⇒ 让路，
  头是词且 `WordArrowAt` ⇒ 让路；深度 0 的 `;` / `,` / 收尾括号即止（内层 `?`:`` 成对抵消）。
- `ParenArrowAt(question, from)`：`( … ) =>` 前瞻（把原 `ArrowFollowsQuestion` 的本体提出来，
  后者变成 `ParenArrowAt(question, range.EndIndex)` 的一行包装）。
- `WordArrowAt(question, from)`：一个词之后（跳过空白）是 `=>`（单参箭头 `x => x`）。
- `IsBuildableHeadChar(ch)`：`{` / 标识符起首 / 数字起首（字符判据与 `DeclarationAsiBoundary`
  同一套，不新造词法表）。

**范围有意收窄**：只让路「字面量分支」与「箭头分支」。`flag ? (a) : 1` / `flag ? a.b : 1` /
`flag ? g(1) : 2` / 内层三目这些「分支是括号 / 成员链 / 调用」的形态本轮**不动**——实测把它们
一起判成让路，会让 `expr-r1233-control-head-regex.ts` 从「整条 legacy（树正确）+ fallback」
变成「增量（树与 TS 有差：`Identifier+1 / ParenthesizedExpression-1 / TypeOfExpression-1 /
CallExpression+1`，来自该文件 `typeof (a)` ⏎ `/re/g` 这条**既有的**增量面残缺）+ 不 fallback」。
那是拿错树换 fallback 数，C10 明确禁止，所以 `(` 只在**确实是箭头**时让路。

## 7. 结论

两条根因都不是箭头体本身：

1. **调用形状没登记身份** ⇒ 收口格不认它是「可带后缀的操作数」，`f(...)` 之后的 `.` / `[` / 模板
   全被判成「未支持续接」。一行 `RegisterNode`（与 [T9]/[R15] 同一条 postfix 通路）清掉
   `im-dynamic` 与 `expr-assert-kernel-member-chain`。
2. **三目的判据只看中段** ⇒ 右段箭头 / 中段或右段字面量在形状里 `Reject`。把闸门扩成
   `HasLegacyBranch`（箭头 + 字面量两种强制让路的头，右段一并看）清掉
   `flag ? 1 : () => 0` 一族与 `stmt-r1242` / `stmt-ternary-statement-boundary`。

30 target、5 smoke、1716 条 AST 指纹逐位不变；fallback 50 → 46，regressed = 0。
