## 3. 根因（两处，各自一句话）

### 3.1 `async` ⏎ `function`：增量分支没有走 `SplitDeclare`

`FunctionDeclarationPossibleShape.ComputeByIndex` 的扫描状态机里，`Stage 6`（已吃下 `async` / `declare`）遇到
`function` 时**本来就有**两条分叉：同一行 ⇒ 认下声明；中间有行终止符 ⇒ `state.SplitDeclare = true`
（注释原文：「ASI split: the modifier is its own ExpressionStatement」）。

但 `BuildByIndex` 的**增量分支**直接 `MountShell(host, start, tokenIndex, shell, …)`，把 `[async .. tokenIndex]`
整段吞进同一个壳；`SplitDeclare` 那条只存在于 legacy 分支。于是壳的 `Data` 以 `Common("async")` 开头，
`FunctionDeclarationShape` 的 builder 按「声明头里有 async」建出 `AsyncKeywordShape`。

`ComputeByIndex` 里那条 `NoNewlineBefore(units, at)`（`LineTerminator.HasBefore`）**本来就是对的**——
所以修点不在判据，在「判据的第二个消费者没接线」。

### 3.2 裸 `yield`：原子候选没有上下文，却把上下文关键字物化了

`IdentifierPrimaryPossibleShape`（A1 的标识符原子）对「初始化器 = 一个词 + 收口」放行，
`yield` 不在它的排除表里（排除表只有 `true/false/null/this/new/typeof/void/in/instanceof`）。
于是生成器里的 `const c = yield` 得到 `IdentifierShape`——而 `yield` 的两种读法**取决于所在的函数体**：
生成器里恒是 `YieldExpression`（操作数可无、可换行），非生成器里只有「同一行后面跟着标识符 / 关键字 / 字面量」才是。

这条判据**已经有唯一一份实现**：`ExpressionBuilder.ParseYield` + `EnclosingFunctionFlags`（第 955 轮那条线，
逐条量过 TS 的六格表）。原子候选既没有祖先链也没有「当前函数是不是生成器」，却抢在它前面把词物化了。

## 6. 未转绿的那一条：`ex-await-yield.ts`（如实记）

- **首跳（修复后）**：`incremental-error`，`step 171`，抛在 `line 9: const d = yield 1` 的 `1` 上，
  异常是 `增量变量形状未支持：declaration 初始化器未读完`（`FunctionDeclarationShape` 本身已经建对：
  文件里 `async function f()` 那半由 R9 的 EOF 收口建出，`function*` 的 `Block` 也不再被上一条吞）。
- **它已经不是原来那一格**：单独取 `const d = yield 1` 是 `ok`；`const c = yield;`（带 `;`）也是 `ok`。
  只有 **`const c = yield` ⏎ `const d = …`（裸 `yield` 收尾 + 无 `;` + 下一条语句在下一行）** 这一格不成立：
  第一条声明的初始化器里只有 raw 单元（`yield` 不再是形状），行尾 ASI 判据 `CanCloseAtLineBreak` 在
  trivia 格上恒假（它要「本条声明最后一个**代码**单元」那一格），于是下一行的 `const` / `d` 被当成初始化器的
  续接吃进 `Data`，收口格的原子建树 `ExpressionBuilder` 读不完 ⇒ 显式抛错。
- **试过且撤回的做法**（两次都**零读数变化**，不留在提交里）：
  ① 在声明终结候选的 trivia 分支补一句「把同一个 `CanCloseAtLineBreak` 问在 `LastCodeIndex` 上」——
  `Accept` 落在了 trivia 格，而列表层 `BuildByIndex` 的 `CanCloseAtLineBreak(host.Data, tokenIndex)` 用同一个
  trivia 下标仍答 `false`，随后 `token` 不是 `Symbol` 直接 `return token`，收口没有发生；
  ② 把该判据抽成 `ClosesAtLineBreak` 并接到列表层两个调用点——矩阵与 3 条目标**一个字节都没变**。
  两次都说明真正的收口点在列表层更靠上的一格（`Common.Close` 链），不在这两个候选里；
  按「不把未验证的行为留在提交里」的规矩撤回，只保留 ①之前那次 `}` 收口（它把 `function* gen(){ const c = yield` ⏎ `}` 从
  **抛错**变成**只差 1 字节的树**：`Block` / `FunctionDeclaration` 的终点多吞 `}` 之后那个换行，
  与 R9 §3 第 5 点同源，是 `[W5:EOF-TRIM]` 那一族，不是本轮判据能覆盖的）。
- **下一轮入手处（不写特判）**：`variable-declaration-list-possible-shape` 的 `CloseAtLineBreak` 触发条件
  （`Common.Close` 那一刻的 `tokenIndex` 语义），而不是在声明终结候选上加第三条近似判据。
