# R10 · BOM trivia 边界：`lex-bom-midcode` 的 `;` 自己归位

分支 `feature/r10-bom`，基线 `905ddc10`（`feature/all-possible`）。对应 R8 审计 #13（类 3）。

**没有接线 `Token.Reclose`**：那一位一个字没动。R8 §3 的判断是对的——`;` 残留是 BOM 把 token 边界推歪的**结果**；
把 BOM 的 trivia 边界修对之后，`;` 与整条语句自己回到正确位置，`Reclose` 不需要。

## 0. 一句话结论

`Bom.Transit` 少了 `WrapSymbol.Transit` / `Symbol.Transit` 都有的那句「先把上一个未关闭的单元收尾」：
BOM 被直接塞进那个**正等着下一个字符来触发关闭**的形状的 `Data` 末尾，于是它成了「最后一个子单元」，
那个 `;` 的收尾再也不发生——语句边界停在 BOM 之前，后面的代码整段并进上一条语句的壳。
补上这最后一步（并 `Reload` 让 BOM 落到新宿主下），`lex-bom-midcode.ts` → `tshape-judge ts` = **ok**。

## 1. 复现与定位（目标 1）

### 1.1 BOM 在哪、`;` 为何留在 `VariableStatement` 下

`tests/cases/token/lexical/lex-bom-midcode.ts`（201 字符，UTF-8）里共有 5 个 BOM，位置 129 / 151 / 172 / 182 / 195：

```
[128] ";"          ← 第一条语句 const a = 1; 的分号
[129] U+FEFF       ← mid-code BOM（就是 R8 说的 [124] 附近）
[130..141] "const b = 2;"
[142] "\n"
[143..150] "function"  [151] U+FEFF  [152] "f" ...
```

修前 `tshape-judge ts` = `structural=5 moved=1`（`VariableStatement-1` `VariableDeclarationList-1`
`VariableDeclaration-1` `Identifier-1` `NumericLiteral-1`，`moved FunctionDeclaration[0] 142-158 vs 129-158`），
也就是**整条 `const b = 2;` 不见了**，而它的 `;` 留在 `VariableStatement@0` 下。

### 1.2 最小复现（12 字符，比 R8 的最小复现还小）

```ts
"const a = 1;const b = 2;"
```

| 输入 | 修前 | 修后 |
| --- | --- | --- |
| `const a = 1;const b = 2;`（无 BOM） | 2 条 `VariableStatement`，边界 `[0,12)` / `[12,24)` | 同左 |
| `const a = 1; const b = 2;`（换成空格） | 同上 | 同上 |
| `const a = 1;\nconst b = 2;`（换成换行） | 同上 | 同上 |
| `const a = 1;␠const b = 2;`（BOM） | **1 条 `VariableStatement` `[0,25)`**，第一个 `;` 丢、第二个 `;` 单独挂在这个壳下 | **与无 BOM 两叉逐字一致**：`[0,12)` / `[12,25)` |

### 1.3 逐字 trace（`tshape-judge steps`，修前）

```text
## step 128 ";"                      ## step 129 BOM                    ## step 130 "c"
VariableStatementShape              VariableStatementShape              VariableStatementShape
└─ VariableDeclarationListShape     └─ VariableDeclarationListShape     └─ VariableDeclarationListShape
   └─ VariableDeclarationShape         └─ VariableDeclarationShape         └─ VariableDeclarationShape
      ├─ IdentifierShape "a"             ├─ ...                              ├─ ...
      ├─ Symbol "="                      ├─ Symbol ";"        ← 还在          ├─ Symbol ";"
      ├─ ...                             └─ Bom  src=[129,130) ← 塞进壳里      ├─ Bom
      └─ Symbol ";"  src=[128,129)                                           └─ Common "c"   ← 新语句的 const 并了进来
```

BOM 被挂到 `VariableDeclarationShape.Data` 的**末尾**（它本来该是那个 `;` 的下一格动作）。
`c` 那一格没有触发任何关闭：它作为 `Common` 直接落进同一个壳。语句直到 step 142 的 `\n` 才关，
此时 `[130,142)` 的 `const b = 2;` 已经在壳里了；再往后 `functionf() {}` 走重建，`pos` 取到 129
（= 那条被吞掉的语句的起点），于是 `FunctionDeclaration` 的 `moved 142-158 vs 129-158`。

## 2. 根因：`Bom.Transit` 少了「先收尾」这一步（目标 2）

`WrapSymbol.Transit`（空白）与 `Symbol.Transit`（标点）开新块之前都有一句同一个形状的守卫：

```ts
const last = unit.Last();
if (last !== null && !last.Closed && last.TryToClose(context) === CloseStates.Built) {
  return BranchStates.Reload;   // 收尾建出了形状：这一格属于新宿主，重放
}
```

`Bom.Transit` 修前**没有**这一句，认下就直接 `unit.Add(mounted)`。这不是「BOM 的位置判据」问题
（`CanStart` 本来就已经「任意位置都认」，用户裁定② 那一步是对的），而是**认下之后怎么落位**的问题：

1. `;` 的关闭是**延迟**的——它等下一个字符（`WrapSymbol` / `Symbol` 的 `Transit` 或形状自己的 `Close`）来问它；
2. BOM 抢在这一步之前把自己挂进了那个还开着的形状，成了 `Data` 的最后一个子单元；
3. 候选判定看到「最后的单元是 BOM」，`;` 的收尾路径不再成立，语句边界就停在 BOM 之前。

对照：空格 / 换行走的是第 1 步那条路——`WrapSymbol.Transit` 先 `TryToClose`，建出语句后 `Reload`，
重放时空白落到**根**下。所以「BOM 当 trivia」不是把 `IsTriviaToken` 改成 `true` 就够了，
**它的挂载时机也必须和别的 trivia 一样：边界定下来之后再挂**。

## 3. 改动（只有一处，1 个文件 +15/−1）

`core/syntax/basic-tokens/bom.xl.md` 的 `Bom.Transit`：

```ts
if (!Bom.CanStart(unit, value)) {
  return BranchStates.Undo;
}
const last = unit.Last();
if (last !== null && !last.Closed && last.TryToClose(context) === CloseStates.Built) {
  return BranchStates.Reload;
}
const mounted = new Bom(unit.Template);
unit.Add(mounted);
mounted.SignIn(index);
mounted.SignOut(index + 1);
mounted.TryToClose(context);
return BranchStates.Done;
```

页面上同时补了「为什么必须先收尾」这一段（BOM 是 trivia，不该改变任何 token 的边界）。

**边界之外一个字没动**：

- `IsTriviaToken` 语义不动（仍是 `true`；`CanStart` 仍是「任意位置都认」）。
- `Bom.Close`（关掉自己后只问父单元）不动——它管的是「BOM 自己这一格」，不是「BOM 抢在收尾之前落位」。
- `Token.Reclose` 没接线（`core/syntax/token.xl.md` 未改）。
- `IMPORTANCE.md` 未改。

修后同一条 trace：

不再被拉到 129，`moved` 消失。

## 5. trivia 口径的旁证（20 条矩阵）

把每个片段里的 `U+FEFF` 换成**一个空格**（长度不变，所以位置可比），要求两棵树的 AST 行**逐字相同**
（过滤 `Bom` / `WrapSymbol` 这两类 trivia 行本身）——即「BOM 与空白作为 trivia 等价」。
20 条里 18 条完全一致，剩下 2 条只差 `text=`：`` `x␠y` `` 与 `/a␠/` 里的 BOM 在**字面量正文之内**，
那段正文本来就该是原文（BOM 不是那里的 trivia）。矩阵覆盖：

`const a=1;␠const b=2;` / `const a=1␠;` / `const a=1;␠`（EOF）/ `␠const a=1;`（首字符）/ 连续两个 BOM /
`class C {}␠const x=1;` / `let a=1;␠\n…` / `function f(){}␠function g(){}` / `[1,␠2]` / `{a:1␠}` / `{␠}` /
`a␠+ 1` / 模板 / regex / 联合类型 / BOM 在行注释前 / `=␠1` / `declare function…␠declare function…` /
`export␠const` / `;␠export const`。
