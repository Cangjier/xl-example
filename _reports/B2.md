## 0. 第 1 回合的判别结果（推翻 A1 的 D-b 前提）

A1 §1 #4/#5 的 `[冲]` 用**当前 bundle 复测**，结论是「宿主其实早已存在」：

| 构造 | `Class/Interface/EnumDeclarationShape` 首见 | `{` 所在 char |
| --- | ---: | ---: |
| `class-field-modifiers.ts`（`class A { … }`） | **step 5**（`class` 关键字闭合格） | 8 |
| `interface-basic.ts` | **step 11**（名字 `I` 闭合格） | 12 |
| `enum-numeric.ts` | **step 6**（名字 `E` 闭合格） | 7 |

所以 `DeferredBracketCatalog.Register + Bind + replay` 对这三个 site **不是**修法：宿主在 `{` 创建时
就在，`ClassDeclarationShape.OnBracketCreatedEvent` 也确实跑了（`BodyGuideUtil.MountBodyGuide` 已装成员目录）。
真正的缺口是**成员候选的语义**：`ClassMemberPossibleUtil.Analyze` / `MemberPossibleUtil.Analyze` /
`EnumMemberPossibleUtil.Analyze` 的 `Complete` 只在「成员边界」（`;` / `,` / 下一行）成立，
所以 `private static readonly x = 1` 的 `PropertyDeclarationShape` 要等到 `;` 之后（step 40），
`a: string` 的 `PropertySignatureShape` 要等到 `string` 之后（step 23）。

**B2 因此按「早建外壳 + 边界换正品」实施**：不改任何 AST 判据，只改「形状什么时候出现」；
正品仍由 `ClassDeclarationShape.BuildMembers` / `InterfaceDeclarationShape.BuildMembers` /
`EnumDeclarationShape.BuildMembers` 产出（`MemberShellCatalog.BuildMember` 用同一个临时括号视图 +
同一套 `Pos` / `End` 断言，见 `class-declaration-shape.xl.md` 的 `BuildMemberFromCode` 口径）。

**为什么成员块目录必须换成安装器**：外壳建出来之后块里不再有新单元，旧目录（`MountBodyGuide` 不带终结候选）
的成员候选会全部 `Reject` → `CatalogGuide` 走「没有候选形状可以构成」的抛错出口。
`BracketCatalogInstaller.BuildGuide` 统一补 `WaitingEndPossible`，把这个出口变成 `Waiting`。

**为什么 `}` 要 `Reload` 交接**：外壳是成员块括号的 `MountedUnit`，`UnitToken.Process` 有挂载单元时
`}` 不会落到括号自己的 `ExitOrPre`（实测会把 `}` 吞成外壳的子 Symbol，`interface-basic` 的
`PropertySignature` 因此吞到 EOF）。外壳先收口、把 `MountedUnit` 置回 `null`、返回 `Reload`，
`}` 由驱动层从根重放一次，落到括号自己的 `ExitOrPre` 正常闭合。

## 3. 未完成项 / 与任务书的偏差（按重要性）

1. **成员的子 token 仍未逐字成形状。** 外壳里装的是**原样单元**（`BuildMembers` 需要 trivia 判 ASI，
   一个都不能丢），所以 `private` / `static` / `readonly` / `x` / `=` / `1` 的
   `PrivateKeywordShape` / `IdentifierShape` / `NumericLiteralShape` 仍只在**换正品那一格**（class 40）
   出现。任务书第 2 条「各自成 token/shape」只做到「整条成员不再是裸 Common」这一层。
   要再往前，得给外壳加第二层目录（逐 token 建修饰词 / 名字 / 字面量），同时保留一份 raw 供换正品——
   设计上可行（`MemberShellEntry` 已带 `Cache`），本轮余量不足。
2. **只覆盖属性成员**：class 的 property、interface 的 property signature、enum 的成员名。
   方法 / 构造器 / 访问器 / 索引签名 / interface 的 call / construct 签名 / enum 计算名仍走旧路径
   （`IsEarlyMemberHead` 对 `(` / `<` 下一字符显式让位；interface 只在 `name :` 提前；enum 只认
   `Common` / `String` 名字）。`class-abstract.ts` 回归就是这条边界的证据（`abstract f(): void` 的
   `void` 曾被误认成员名，已用「修饰词链后必须只剩名字这一格」挡住）。
3. **`DeferredBracketCatalog.Drop` 挂 `Quit`/`Undo` 未落地**：B2 不登记 Deferred 条目（宿主一直存在），
   `BracketRoleReplayFailureCount` 恒 0 是**因为没有 replay**，不是因为 Drop 接好了。
   等价物是 `MemberShellCatalog.Prune`（外壳脱离父单元 / 收口格越过时摘条目），已实现并在
   `Create` / `FinalizeAll` 里调用；本轮所有用例 `pruned = 0`。
4. **`export class` 在根层晚建壳（S3 §6.1 交接项）没做**：B2 只处理「壳在关键字格建出」的声明；
   根层 `export <decl>` 的挂壳格不动（S3 已说明会翻 `moved` 基线）。
5. **B0a 的一个 bug（不是本 WP 引入，未修）**：`DeferredBracketCatalog.Bind` 先把命中条目 `Drop`
   再调 `Replay`，而 `Replay` 用 `Find(bracket)` 取 `plan` ⇒ 永远取到 `null` ⇒
   `ReplayFailureCount += 1`、replay 永不成功。谁先用 Deferred 谁必须先修这一条
   （把 plan 作为参数传进 `Replay`，或先 replay 后 `Drop`）。B2 的路径绕开了它。
6. `tmp/` 下的探针（`firstseen.mjs` / `probe-counters.mjs` / `probe-incremental.mjs` /
   `class-min.ts` / `enum-min.ts` / `ast.mjs`）是诊断用，`tmp/` 已 gitignore，未提交。
