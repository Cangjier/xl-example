## 2. 第二步：判据对齐（只在失败族正好是「5 条 lib + 32 差异 + 94 fallback」之后做）

### 2.1 改了什么

| 文件 | 改动 | 为什么只能改这里 |
| --- | --- | --- |
| `tests/parse/incremental-crash-expected.mjs` | **新增**：`INCREMENTAL_CRASH_EXPECTED`（5 条 lib）、`INCREMENTAL_POLICY`（5/87/94）、`LEGACY_POLICY`（0/0/2）、`unexpectedCrashes()`、`expectedCrashList()` | 现在**两把尺子**（`wide-ast` / `real-dts-ast`）读同一份清单；两处各抄一份就会漂，而漂了的症状正是「白名单悄悄多一条」 |
| `tests/parse/wide-ast.mjs` | ① 默认档 = 增量（不拨开关），新增 `--legacy`（压回 false）、`--incremental-on` 降为别名；② 判据：增量档 **`policyProblems === 0` 即 exit 0**；③ 缺 range / 越界在增量档也进 `policyProblems`；④ PASS/FAIL 行印出**阈值 + 5 条清单** | 判据与阈值只在这个文件 / 那个共享模块里定义 |

| `tests/gates/run.mjs` | ① 默认档 = incremental；② `--legacy` 只给标了 `usesTier` 的两道门加参数（**门数仍是 11**）；③ 删掉 `wide-ast:incr` 第 12 道（那正是两套读数打架的来源）；④ 档位/阈值/清单印在头尾 | 门名单与档位只写在 `GATES` 这一处 |

### 2.2 新判据（一句话）

- **incremental（默认）**：`崩溃 ≤5 且集合逐字等于那 5 条 `lib.*.d.ts``、`差异 ≤87`、`fallback ≤94`、
  `distOnlyKinds 0`、白名单卫生、`缺 range 0`、`越界 0` ⇒ **`policyProblems === 0` ⇒ exit 0**。
- **legacy（`--legacy`）**：`崩溃 + 差异 + 缺 range + 越界 > 0` 即红；天花板 0 / 0 / ≤2。

**为什么这样不是放宽**：`policyProblems` 是**全部**判据的与，不是它的子集；清单**逐字比对**
（`unexpectedCrashes` 返回非空即红），所以「换一个文件崩」仍然红 —— 实测反例：
把 `tests/cases/token/expressions/ex-await-yield.ts` 塞进崩溃集合，增量档立刻点名它；
legacy 档下这 5 条 lib 崩溃**也全部**算意外。天花板 5/87/94 一个数没动。

## 6. 边界与残留

1. **判据的取舍写在明处**：增量档「有差异 ≠ 红」，靠的是 `policyProblems` 里逐条登记的天花板与清单。
   `D5 §5.1` 记过「ON 档一进默认池就永久红一片、红里分不出真假」；本波是把「已知的 32」与「新冒出来的」
   分开，不是把红吞掉 —— `--legacy` 一次就能看到 0/0/2 的对照。
2. **`--incremental` 不再是第 12 道门**：它只是默认档的别名。同一把尺子量两遍会给出两个可能互相矛盾的
   读数（M-W6 §4.1 的 4 PASS / 1 FAIL 就是那次冲突），所以删掉的是**重复的门**，不是判据。
3. **文档里的「默认 false」还在**（不在本波写域，交文档 owner）：`docs/token-time-shapes-incremental.md:12`
   与 `tests/parse/token-time-shapes.mjs` 的注释仍写 `默认 false`。工具行为不受影响（它显式拨开关），
   但句子已经是旧事实；正确的现状写在 `statement-route-util.xl.md` 的两个字段节里。
4. **`EnableBracketRoleCatalog` 仍 `false`**：B0 只建机制、不迁 site，按指令未动。
5. **未合并 / 未 push / 未删目录**：工作副本 `xl-example-set\d7-default` 保留，分支 `feature/d7-default`。
