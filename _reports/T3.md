## 1. 复现：026 的首跳**不在** block / body 挂载

`if (/x/.test(s)) {}`，开关关闭时**也**是 fallback（T2 读数 29/1 里的那 1 条），所以问题不是「打开
BracketCreate 才炸」。逐层实测：

| 假设 | 读数 | 结论 |
|---|---|---|
| `TryMountControlFlowBody` 被 `IfStatementShape` 占位标记挡住（T6 的猜测） | `ControlFlowBodyBraceCount = 1`（开 / 关都是 1）；`StatementShape.Data` 里 `IfStatementShape` 的 `IsTriviaToken = true`，head 扫描本来就跳过它 | **不成立**：块体目录照常挂上了 |
| `BlockPossibleShape` 没读 `source` | `BracketCreateParentCount = 0`（026 的 `{` 宿主是语句壳、不是括号，触发点按旧窄域本来就不问父层）；就算问了也不影响建树 | **不是这条** |
| 控制头候选提前把成员名建成头原子 | `ControlHeadAtomCount = 1`（关）/ `0`（开修复后）；`ParseCore(shell=true)` 的内层异常栈直指 `ExpressionBuilder.ParseName` | **根因** |

首跳（`SourceFileRunner.ParseCore(source, "case.ts", true)` 的内层异常，关档）：

```
SyntaxException: line 1: if (/x/.test(s)) {}
line 1:                  ^^
  ← Error: 缺少标识符
     at ExpressionBuilder.ParseName
     at ExpressionBuilder.ParsePostfixSuffix   // `.` 之后
     at StatementBuilder.BuildIf → ParseBracketExpression
```

机理：控制流头的 `(` 挂 `ControlHeadPossibleShape`，它把 `test` 换成了 `IdentifierShape`（头原子）。
legacy 的 `ParsePrimary` 认这张表，但**成员链的名字位**走 `ParsePostfixSuffix` → `ParseName`，
`ParseName` 只认 `Common` / `ExpressionAtomRegistry`（头原子不进那张表）⇒ `.` 后面无标识符可读 ⇒
整条文件回退 legacy。`ExpressionBracketPossibleShape.IsBuildable` 早就为 `.` / `?.` 之后的标识符
做了同一件事（让位给 legacy），控制头候选漏了这一条——026 是唯一实测缺口。

## 2. 修法（通用，不是 if + RegexToken 特判）

`ControlHeadPossibleShape` 新增 `IsMemberName(unit)`：同一 `Data` 里前一个非 trivia 单元是
`.` / `?.` ⇒ 这一格**不建头原子**，保持 raw `Common` 交给 legacy 成员链。对 `if` / `while` / `for` /
`switch` / `with` 全部一致，`?.` 同样覆盖。

- 生效条件：`StatementRouteUtil.EnableBracketCreatePossible`（T2 的开关）。关闭时判据逐字节是 T2 之前
  （关档仍是 29/1，026 仍 fallback）；打开时 026 转 ok。
- 为什么挂在开关上：验收要求「关 29/1、开 30/0」，而这条让位是 026 的唯一修法；G1 决定翻 `true` 之后
  它与 `ExpressionBracketPossibleShape` 的无条件让位汇合，开关本身可以退化成纯触发开关。
- 为什么不是「让 `TryMountControlFlowBody` 跳过 `IfStatementShape`」：占位节点是 trivia，head 扫描
  本来就跳过；改它只会是无人调用的防御代码，所以**没改**（有读数为证）。
