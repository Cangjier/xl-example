## 3. 根因

### 3.1 族 P：类型面在 `)` 格看到 `=>`，把半截初始化器落了地

`typescript/tokens/types/type-catalog-factory.xl.md` 的 `CanEndInitializer` 决定**类型面什么时候提前落地**
（`VariableDeclarationShape.TryBuildTypedInitializer` 的唯一闸门）。它的结束字符集是

```ts
static field InitializerEnd:string = ";,)]}="
```

`=` 在里面——T8d 已经收窄过「`=` 后面还是 `=`（`==` / `===`）不算终点」，但**`=` 后面是 `>`（`=>`）仍然算终点**：

1. `const g: F = (a) => a;` 的注解 `F` 落地（`AnnotationDone = true`）；
2. 形参表 `(a)` 在 `)` 格关闭，`CanEndInitializer` 看到下一个字符是 `=`（其实是 `=>`）⇒ 判「初始化器已完整」；
3. `TryBuildTypedInitializer` 用 `ParseInitializer` 把当时那段 raw（`(a)`）建成 `ParenthesizedExpressionShape` 并落地；
4. 之后 `=>` / `a` 再进来没人接，收口格 `FinishIncremental` 看到「唯一根 + 根之外还有代码」
   （或 `=>` 落在根之外）⇒ C10 显式抛错 ⇒ 整文件回退 legacy。

`const g: F = () => 1;` 之所以 ok：`()` 里的 `ParseInitializer` 建不出东西 / 落地不进同一条链，恰好躲过。
**判据不在箭头建树处**——所以 T8c §3 记的「在守卫处打补丁会得到 `((x)=>typeof x) === "string"`」这条坑不适用：
本轮动的是**类型面的落地时机**，raw 里是整条箭头，`ParseInitializer` 与 legacy 同源。

### 3.2 族 C：箭头块体 `}` 之后没有 ASI 边界，下一行正则被吞进初始化器

`const v = () => { }` ⏎ `/re/g;` 的逐字符 trace（`tmp/t10-trace-c1/`）在最后一格是：

```text
│  ├─ Symbol  src=[36,38)  text="=>"
│  ├─ Bracket src=[39,42)            ← 块体，仍是 basic 括号（未建成 BlockShape）
│  ├─ WrapSymbol src=[42,43) text="\n"
│  └─ RegexToken src=[43,48) text="/re/g"   ← 整条被吞进声明的 Data
```

- `(a) => { }` 这条箭头**不是**增量建的（`EnableArrowParenCatalog=false`，`Family` 是 `"paren"`，
  `CompositeInitializerFormsJudge.CanBuild` 要求「之后只剩输入结束」，`/re/g` 在就不成立），
  所以声明 `Data` 里是 raw `( ) => { }`；
- 块体 `}` 那一格，`VariableDeclarationEndPossibleShape` 的 `Bracket` 分支只做 `Reject`（继续等），
  收口判据 `CanCloseAtLineBreak` / `CanClose` 只在 trivia / `Common` 格成立；
- `DeclarationAsiBoundary.StartsNewStatementLine` 只认「下一行起一个**单词**」，`/` 不是单词起点 ⇒ 判不出边界；
- 于是 `/re/g` 作为未知单元落到 `VariableDeclarationEndPossibleShape` 的兜底 `Reject`（等），被 `Add` 进 Data；
- 到 `;` 收口，`FinishIncremental` 的 `builtShape === null` 分支用 legacy `ExpressionBuilder`
  读 `( ) => { } /re/g`——**legacy 建造器在块体箭头之后不接二元运算符** ⇒ `builder.At !== Units.length`
  ⇒ 显式抛「初始化器未读完」⇒ 整文件回退。

TS 的实测口径（`ts.createSourceFile`，本轮亲自跑过）：

| 源码 | TS 语句 |
|---|---|
| `const v = () => { }` ⏎ `/re/g;` | `[0,19)` 声明 + `[19,26)` **正则语句**（两条） |
| `const v = function () { }` ⏎ `/re/g;` | 一条（**除法**） |
| `const v = {}` ⏎ `/re/g;` | 一条（除法） |

差别只在「这个 `}` 是不是**箭头箭杆所接的块体**」——判据因此可以只看**紧邻的前一个代码单元是 `=>`**。

## 4. 改动（2 个文件，+128 / −6；语义 2 处）

### 4.1 `typescript/tokens/types/type-catalog-factory.xl.md` — `CanEndInitializer` 一行判据

```ts

```

`ParseInitializer`（legacy 同一个 `ExpressionBuilder`）——建出来的树与 legacy 同源，不是第二套表达式机。
文档同步改写（原文写着「`=>` 不受影响」，那句话现在不成立）。

**没做什么**：不新增 guide、不碰箭头建树代码、不改 `(x: T) => …` 这一类**不带注解**箭头的落地时机
（它们在 `)` 格本来就过不了 `ParseInitializer`，`CanEndInitializer` 改不改都落不了地，实测矩阵 20 条全 ok）。

### 4.2 `typescript/tokens/declarations/forms/declaration-asi-boundary.xl.md` — 新增一条边界判据

新增 `ArrowBodyCloseStartsStatement(units, tokenIndex)`：本格是**已闭合的 `{` 括号**、前一个代码单元是
`=>`、且跨过行终止符（可跳过注释）的第一个显著字符是 `/`（且不是 `//` / `/*`）⇒ 这一格就是语句边界。

它接进 `CanCloseAtLineBreak` 的两处（既有路径，不新写收口动作）：

- 在「尾巴判据 `CanEndDeclarationTail` 不成立」的 bail 里多一个放行项
  （`CanEndDeclarationTail` 对裸 `{` 括号恒 `false`，因为 `CanEndExpression` 分不清块体与对象字面量）；
- 最终 `return` 里与 `StartsNewStatementLine` / `IsBlockHostBoundary` 并列为第三条边界来源。

收口仍走既有 `VariableDeclarationListEndPossibleShape` → `CloseAtLineBreak`：声明在 `}` 那一格原地收口
（`Data` 里就是 `( ) => { }`，legacy 原子建出正确的 `ArrowFunctionShape`），下一行的 `/re/g;` 回到父单元
重新建壳成一条正则语句。

三条反向边界：同行 `/` 不算（必须跨行，否则是除法）；`//` / `/*` 是注释不是语句起点；
文档不可用（探针）⇒ `false`。`function () { }` / `{}` / `class {}` / 调用实参里的箭头块体都不命中
（前驱不是 `=>`，或那一格不是声明最后一个代码单元）。

**没做什么**：不新增 guide、不碰 `ContainerCloseGuide`、不删 `StatementShape`、不动任何箭头建树判据、
不改 30 target 行为、不跑 gates。

## 8. 结论

箭头族本轮取两条**独立**的根因、清掉 3 个 fallback（57 → 54）：

1. **类型面在 `=>` 提前落地**（`CanEndInitializer` 的 `=` 只认 `==`，不认 `=>`）——一条判据，
   与 T8d 修 `==` 是同一处、同一个理由；
2. **箭头块体之后的 ASI 边界**（`DeclarationAsiBoundary` 只认「下一行起一个单词」）——新增一条
   「`=>` 块体 `}` + 换行 `/`」的边界判据，接进既有 `CanCloseAtLineBreak`，不新写收口动作。

30 target、5 smoke、1716 条 AST 指纹逐位不变；T8c 记的「形参带类型 + `===`」面用独立矩阵复核为已关闭。
